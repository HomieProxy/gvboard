# Gvboard 插件开发与安装说明

Gvboard 支持两种插件：

| | 内置插件（Go） | JS 插件 |
|---|---|---|
| 安装方式 | 放进源码 `plugins/`，重新编译程序 | 管理端“插件管理”上传 zip，无需重新编译、无需重启 |
| 能力 | 完全访问数据库；事件、过滤器、路由、定时任务、支付方式、订阅格式 | 受限环境：事件、过滤器、路由、定时任务；只能访问声明过的域名与权限 |
| 适合 | 支付网关、深度定制、性能敏感的功能 | 通知推送、签到、简单营销活动等 |
| 安全 | 与面板同等权限，只安装信任的代码 | 沙箱运行，安装前管理端显示其申请的权限与域名 |

两种插件安装后都**默认停用**，需要在管理端“插件管理”中启用；有配置项的插件点击齿轮图标配置。多实例部署时启用、停用、配置会自动同步到各实例。

仓库中自带的示例：

| 示例 | 类型 | 位置 | 演示内容 |
|------|------|------|----------|
| 每日签到（随机余额） | 内置 | `plugins/checkin` | 用户端卡片、用户路由、KV 存储、修改余额 |
| Webhook 推送 | 内置 | `plugins/webhook` | 订阅事件、签名、外部请求 |
| 首单优惠 | 内置 | `plugins/firstorder` | 过滤器（修改下单金额并写明细、套餐标签）、用户端卡片（跳转按钮）、查询数据库、配置校验 |
| 每日签到送余额 | JS | `examples/js-plugins/daily-bonus` | 用户端卡片、用户路由、KV、`users.addBalance` |
| 订单与工单通知 | JS | `examples/js-plugins/order-notify` | 订阅事件、外部请求（Telegram / 企业微信 / 钉钉 / Bark）、启用回调 |

## 1. 安装 JS 插件（以“订单与工单通知”为例）

### 1.1 打包

把插件目录中的 `plugin.json` 与 `main.js` 压缩为 zip（zip 根目录直接是这两个文件，或者只有一层顶级目录都可以）。

Windows（PowerShell，在项目根目录执行）：

```powershell
Compress-Archive -Path examples\js-plugins\order-notify\* -DestinationPath order-notify.zip -Force
```

Linux / macOS：

```bash
cd examples/js-plugins/order-notify
zip -r ../../../order-notify.zip plugin.json main.js
```

也可以在文件管理器中选中这两个文件，右键“压缩为 zip”。

### 1.2 上传与安装

1. 登录管理端 → 左侧菜单“插件管理” → 右上角“上传 JS 插件”。
2. 选择 zip 文件 → 点击“检查安装包”。页面会显示插件信息、**申请的权限**（本例：读取用户基本信息，用于在消息中显示用户邮箱）与**可访问的域名**（本例：Telegram、企业微信、钉钉、Bark 的接口域名）。
3. 确认无误后点击“确认并安装”。插件出现在列表中，启用开关为关闭状态。

升级：修改代码后（记得改 `version`）重新打包上传，同一 `code` 的插件会被替换并立即生效，配置与启用状态保留。

### 1.3 配置并启用

1. 在插件列表点击齿轮图标“配置”，按渠道填写：

   | 渠道 | 需要填写 | 获取方法 |
   |------|----------|----------|
   | Telegram 机器人 | 机器人 Token、Chat ID | 在 @BotFather 创建机器人得到 Token；先给机器人发一条消息，再用 @userinfobot 等查询自己的 Chat ID（群组 ID 以 `-` 开头） |
   | 企业微信群机器人 | Webhook 地址 | 群聊 → 右上角 → 群机器人 → 添加，复制 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...` |
   | 钉钉群机器人 | Webhook 地址 | 群设置 → 机器人 → 自定义机器人，安全设置选“自定义关键词”并填写 `通知`，复制 `https://oapi.dingtalk.com/robot/send?access_token=...` |
   | Bark（iPhone） | 设备 Key | 在 Bark App 首页复制地址中 `https://api.day.app/` 后面的那段 |

2. 选择要通知的事件（付款、新工单 / 提现申请、新用户注册），保存。
3. 打开插件的启用开关。启用时插件会先发送一条“插件已启用”测试消息，**发送失败时不会启用**，并提示失败原因（例如 Token 错误）。

之后用户付款、提交工单时即会收到推送。推送失败时队列最多重试 3 次，失败原因（警告、错误级别的日志）可在管理端“系统日志”中查看。

### 1.4 删除

停用后点击垃圾桶图标删除。插件的 KV 数据随之删除。

## 2. 安装内置插件（以“首单优惠”为例）

内置插件是 Go 代码，编译进程序。`首单优惠` 已随本仓库提供并已注册，**直接使用发布的程序即可在“插件管理”中看到它**，跳到 2.3 启用即可。下面以它为例说明自己新增一个内置插件的完整流程。

### 2.1 放入源码并注册

1. 在 `plugins/` 下新建目录，例如 `plugins/firstorder/`，放入插件代码（包内 `init()` 中调用 `plugin.Register`）。
2. 编辑 `plugins/all.go`，增加一行匿名导入：

   ```go
   import (
   	_ "gvboard/plugins/checkin"
   	_ "gvboard/plugins/firstorder"
   	_ "gvboard/plugins/webhook"
   )
   ```

第三方发布的 Go 插件同理：可以把代码复制到 `plugins/` 下，或 `go get` 其模块后在 `all.go` 中导入其包路径。

### 2.2 重新编译并替换程序

```bash
cd Gvboard
go test ./plugins/...                                    # 可选：运行插件自带的测试
go build -trimpath -ldflags "-s -w" -o gvboard ./cmd/gvboard
```

在 Windows 上为 Linux 服务器编译（PowerShell）：

```powershell
$env:GOOS = "linux"
$env:GOARCH = "amd64"
go build -trimpath -ldflags "-s -w" -o gvboard ./cmd/gvboard
Remove-Item Env:GOOS
Remove-Item Env:GOARCH
```

把新程序上传到服务器、替换旧文件后执行 `./gvboard migrate` 并重启服务（与“升级”步骤相同，见部署文档第 11 节）。多实例部署时每个实例都要替换。

### 2.3 配置并启用

管理端“插件管理”中找到“首单优惠”，点击齿轮图标配置：

| 配置项 | 说明 |
|--------|------|
| 减免比例（%） | 1～100，例如 20 表示首单 8 折；100 表示首单免费 |
| 最多减免（分） | 例如 1000 表示最多减 10 元；0 表示不限制 |
| 适用套餐 ID | 例如 `1,3`；留空表示全部套餐 |

保存后打开启用开关（配置不合法时无法启用）。从未购买过套餐（充值不算）的用户新购套餐时，结算金额会自动按比例减免（在优惠券之后计算）。启用后对符合条件的用户：

- 仪表盘“活动”区块显示“首单优惠”卡片，按钮跳转到套餐页；用户购买过套餐后卡片自动消失。
- 套餐页与结账页的套餐上显示“首单立减 N%”标签。
- 结账页金额明细中显示“首单优惠 -¥x”，下单后订单详情（用户端与管理端）保留该明细。

自制主题也可以调用 `GET {API 前缀}/plugin/first_order/eligible` 判断当前用户能否享受首单优惠。

> 注意：首单优惠按账号判断，可能被批量注册账号薅羊毛，建议同时开启注册验证码、邮箱验证或限制注册频率。

## 3. 开发 JS 插件

### 3.1 目录结构

```
my-plugin/
├── plugin.json   # 清单（必需）
├── main.js       # 入口（可在 plugin.json 的 main 中修改）
└── lib/util.js   # 可选，main.js 中 require('./lib/util') 引入；也可 require JSON 文件
```

限制：zip 不超过 2 MB、最多 200 个文件、解压后不超过 8 MB；`.js` 文件必须为 UTF-8。

### 3.2 plugin.json

```json
{
  "code": "order_notify",
  "name": "订单与工单通知",
  "version": "1.0.0",
  "author": "作者",
  "description": "说明",
  "main": "main.js",
  "http": ["api.telegram.org", "*.example.com", "api.example.net:8443"],
  "permissions": ["user.read"],
  "config": [
    { "key": "channel", "label": "推送渠道", "type": "select", "default": "telegram", "required": true,
      "options": [{ "value": "telegram", "label": "Telegram" }] },
    { "key": "token", "label": "Token", "type": "password", "help": "填写说明" }
  ]
}
```

| 字段 | 说明 |
|------|------|
| `code` | 插件标识：小写字母开头，只能包含小写字母、数字、下划线、短横线，2～32 个字符；用于路由路径与数据存储，发布后不要修改 |
| `version` | 版本号 |
| `http` | 允许访问的域名（最多 20 个）。`*.example.com` 表示其子域名；不写端口时只允许 80 / 443；不能填写 IP。内网地址始终禁止访问 |
| `permissions` | 申请的数据权限，见下表 |
| `config` | 配置项，管理端据此生成表单。`type`：`string` 单行文本、`text` 多行文本、`password` 密钥、`number` 数值、`bool` 开关、`select` 单选（需 `options`） |

| 权限 | 允许 |
|------|------|
| `user.read` | `users.get` / `users.findByEmail`：读取用户基本信息（不含密码） |
| `user.balance` | `users.addBalance`：增加或扣除余额 |
| `subscription.read` | `subscriptions.get` / `subscriptions.list`（不含订阅令牌与 UUID） |
| `subscription.write` | `subscriptions.addTraffic` / `subscriptions.extend` |
| `order.read` | `orders.get` / `orders.list` |

### 3.3 可用的全局对象

```js
// 注册（只能在脚本顶层调用）
plugin.on('order.paid', function (ev) { ev.name; ev.time; ev.data; });          // 订阅事件
plugin.filter('order.amount', 10, function (v) { v.amount = Math.floor(v.amount * 0.9); return v; }); // 过滤器，priority 小的先执行
plugin.route('user', 'POST', '/checkin', function (req) { return { ok: true }; }); // 路由：guest / user / admin
plugin.job('daily_report', '0 9 * * *', function () { });                       // 定时任务（5 段 cron）
plugin.widget({ key: 'checkin', slot: 'dashboard', title: '每日签到', icon: 'gift', state: '/widget' }); // 用户端卡片（见第 5 节）
plugin.onEnable(function () { });   // 启用前调用，抛出异常则不启用（可用于校验配置）
plugin.onDisable(function () { });

// 运行时
plugin.code; plugin.info; plugin.config();          // 插件标识、信息、当前配置
plugin.fail(400, '错误提示');                        // 在路由中返回错误
plugin.response({ status: 200, headers: {}, body: '...' }); // 自定义原始响应
kv.get(key); kv.set(key, value, ttl秒); kv.setnx(key, value, ttl秒); kv.del(key); // 插件专属存储（字符串）
http.get(url, opts); http.post(url, body, opts); http.request({ method, url, headers, body, json, timeout }); // 返回 { status, headers, body, json() }
log.info(...); log.warn(...); log.error(...);       // console 同 log
crypto.sha256(s); crypto.hmacSHA256(key, s); crypto.randomHex(n); crypto.base64Encode(s); crypto.base64Decode(s);
users.get(id); users.findByEmail(email); users.addBalance(id, 分);
subscriptions.get(id); subscriptions.list(userID); subscriptions.addTraffic(id, 字节); subscriptions.extend(id, 秒);
orders.get(tradeNo); orders.list(userID, limit);
```

路由处理函数的 `req`：`method`、`path`、`ip`、`params`、`query`、`headers`（不含 Authorization 与 Cookie）、`body`（字符串）、`json()`、`user`（`id`、`email`、`is_admin`、`is_staff`，访客路由为 `null`）。返回普通对象时以 `{ "data": ... }` 输出。

路由地址：

| 类型 | 地址 |
|------|------|
| `guest` / `user` | `{API 前缀}/plugin/{code}/路径`（`user` 需携带用户登录凭证） |
| `admin` | `{API 前缀}/{管理端路径}/plugin/{code}/路径` |

### 3.4 事件与过滤器

| 事件 | `ev.data` 字段 |
|------|----------------|
| `user.registered` / `user.login` | `user_id`、`email`、`invite_user_id`、`ip` |
| `order.created` / `order.paid` / `order.opened` / `order.cancelled` | `trade_no`、`user_id`、`plan_id`、`period`、`type`（1 新购、2 续费、3 升级、4 流量重置包、9 充值）、`status`、`total_amount`（分）、`balance_amount`、`subscription_id` |
| `subscription.changed` | `subscription_id`、`user_id`、`action`、`trade_no` |
| `ticket.created` / `ticket.replied` | `ticket_id`、`user_id`、`subject`、`kind`（created / withdraw / replied）、`message`、`by_admin` |
| `traffic.reported` | `server_type`、`server_id`、`users`、`upload`、`download` |

事件在业务完成后异步处理，处理函数抛出异常时最多重试 3 次，因此**处理函数要能重复执行**（例如用 `kv.setnx` 去重）。

过滤器在业务进行中同步调用，按 priority 从小到大依次执行；处理函数抛出异常或返回的值不合法时，忽略该插件这一次的修改，继续执行后面的插件。

| 过滤器 | 值 | 可修改 |
|--------|----|--------|
| `order.amount` | `user_id`、`plan_id`、`period`、`subscription_id`、`type`、`amount`、`items`、`preview` | `amount`（分，不能为负）、`items`（追加本插件的金额明细） |
| `plan.badges` | `user_id`（访客为 0）、`plans`（`[{ plan_id, badges }]`） | 各套餐的 `badges`（标签文字） |
| `subscribe.servers` | 订阅下发的节点列表 | 节点列表 |
| `subscribe.content` | 生成的订阅内容 | `content_type`、`headers`、`body` |
| `knowledge.article` | `user_id`、`article_id`、`locale`、`available`（用户是否有可用订阅）、`body`（文章 HTML） | `body`（最大 1 MB，不能清空） |

**修改下单金额时写明细**：修改 `amount` 的同时向 `items` 追加 `{ label, amount }`，`label` 为用户看到的名称（1～32 个字符），`amount` 为调整金额（分，减免为负数）。用户端结账页实时显示这些明细，下单后保存到订单，用户端与管理端订单详情都能看到。规则：

- 每个插件最多追加 3 条，本插件追加的明细金额合计必须等于本插件对 `amount` 的修改，否则忽略本次修改。
- 只改了 `amount` 没有写明细时，自动以插件名称生成一条。
- 减免金额计入订单的优惠金额。
- 不要修改 `items` 中其他插件的明细。

`preview` 为 `true` 表示用户在结账页试算（尚未下单），这时插件不要扣减次数、发放奖励等，只计算金额。

```js
plugin.filter('order.amount', 10, function (v) {
  if (v.type !== 1) return v;
  var off = Math.floor(v.amount * 0.1);
  v.amount -= off;
  v.items.push({ label: '新人九折', amount: -off });
  return v;
});
```

**套餐标签**：`plan.badges` 在用户端套餐列表、套餐详情（结账页）调用，插件向 `badges` 追加标签文字（每个套餐最多 3 个、每个最多 16 个字符），用户端显示在套餐名称旁，如“首单立减 20%”。`user_id` 为当前用户，可按用户判断是否显示。

```js
plugin.filter('plan.badges', 10, function (v) {
  v.plans.forEach(function (p) { p.badges.push('限时特惠'); });
  return v;
});
```

**知识库文章**：`knowledge.article` 在用户打开知识库文章时调用，适合把文章中的占位符（如 `{apple_id}`）替换为插件生成的内容。调用时访问限制区块（`<!--access start-->` … `<!--access end-->`）已按用户是否有可用订阅处理、`{{subscribeUrl}}` 等变量已替换，没有可用订阅时区块内的占位符不会传给插件。注意：

- `body` 按 HTML 显示，插件拼接的外部数据（接口返回的账号等）必须先转义 `& < > " '`；
- 文章显示在独立的区域中，`<script>` 不会执行，也不要写 `onclick` 这类内联事件，交互使用下面的复制属性；
- 过滤器最多执行 10 秒，请求外部接口时设置较短的超时并用 `kv` 缓存结果。

**复制按钮**：文章与公告中带 `data-copy` 属性的元素，点击时复制属性值并提示“已复制”，复制成功后 1.5 秒内带有 `data-copied` 属性，可用于切换按钮样式：

```js
plugin.filter('knowledge.article', 10, function (v) {
  if (v.body.indexOf('{apple_id}') < 0) return v;
  var html = v.available ? '<button data-copy="' + esc(account) + '">复制账号</button>' : '<p>需要有效订阅</p>';
  v.body = v.body.split('{apple_id}').join(html);
  return v;
});
```

`esc` 为插件自己的转义函数；样式可以写在 `body` 中的 `<style>` 里，颜色使用主题变量（如 `var(--card)`、`var(--border)`、`var(--primary)`）即可适配暗色模式。

### 3.5 调试建议

- 本地运行一个 Gvboard（见部署文档），上传插件后调试：`log.warn` / `log.error` 与运行报错会写入管理端“系统日志”；`log.info` 只输出到程序日志（终端、`journalctl -u gvboard` 或宝塔守护进程日志）。
- 安装时会检查语法与 plugin.json；脚本顶层抛出异常时插件显示“加载失败”及原因。
- 每次调用有执行时间与内存限制，不要在插件中做大量循环或保存大对象。

## 4. 开发内置插件（Go）

最小示例：

```go
package hello

import (
	"context"

	"github.com/gin-gonic/gin"

	sdk "gvboard/pkg/plugin"
)

func init() { sdk.Register(&Plugin{}) }

type Plugin struct{}

func (Plugin) Info() sdk.Info {
	return sdk.Info{Code: "hello", Name: "示例", Version: "1.0.0", Author: "我"}
}

// 可选：配置项
func (Plugin) Fields() []sdk.Field {
	return []sdk.Field{{Key: "greeting", Label: "问候语", Type: sdk.FieldString, Default: "你好"}}
}

// 可选：启用前校验，返回错误则不启用
func (Plugin) Enable(ctx context.Context, h sdk.Host) error { return nil }

// 进程启动时调用一次，注册的功能只在启用后生效
func (Plugin) Setup(h sdk.Host) error {
	h.On(sdk.EventOrderPaid, func(ctx context.Context, e sdk.Event) error {
		var o sdk.OrderEvent
		if err := e.Decode(&o); err != nil {
			return err
		}
		h.Log().Info("订单已支付")
		return nil
	})
	sdk.AddFilter(h, sdk.FilterOrderAmount, 10, func(ctx context.Context, v sdk.OrderAmount) (sdk.OrderAmount, error) {
		off := v.Amount / 10
		v.Amount -= off
		v.Items = append(v.Items, sdk.AmountItem{Label: "新人九折", Amount: -off})
		return v, nil
	})
	sdk.AddFilter(h, sdk.FilterPlanBadges, 10, func(ctx context.Context, v sdk.PlanBadges) (sdk.PlanBadges, error) {
		for i := range v.Plans {
			v.Plans[i].Badges = append(v.Plans[i].Badges, "限时特惠")
		}
		return v, nil
	})
	h.UserRoutes().GET("/hi", func(c *gin.Context) {
		sdk.OK(c, h.Config().String("greeting")+"，"+sdk.CurrentUser(c).Email)
	})
	h.Job("cleanup", "0 4 * * *", func(ctx context.Context) error { return nil })
	return nil
}
```

`sdk.Host` 还提供 `KV()`（插件专属存储）、`DB()`（与面板共用的数据库连接，请谨慎操作）、`GuestRoutes()` / `AdminRoutes()`、`Payment()`（新增支付网关）、`SubscribeFormat()`（新增订阅格式）、`Widget()`（用户端卡片，见第 5 节）。完整接口见 `pkg/plugin/` 中的注释。

开发完成后按第 2 节注册、编译、启用。建议为纯逻辑部分编写单元测试（参考 `plugins/firstorder/firstorder_test.go`）。

## 5. 用户端卡片

插件可以在用户端仪表盘放置卡片，例如签到、抽奖、活动入口，不需要修改前端。卡片显示在仪表盘数据卡片下方的“活动”区块，没有卡片时不显示该区块。

卡片是**声明式**的：插件只提供标题、图标、说明文字、数值和最多 2 个按钮，用户端按统一样式以纯文本显示，插件不能向页面插入 HTML 或脚本。

### 5.1 注册

| 字段 | 说明 |
|------|------|
| `key` | 插件内唯一的标识：小写字母开头，只能包含小写字母、数字、下划线，最多 32 个字符 |
| `slot` | 位置，目前只有 `dashboard`（仪表盘） |
| `title` | 标题，最多 32 个字符 |
| `icon` | 图标：`puzzle`（默认）、`gift`、`calendar-check`、`star`、`trophy`、`ticket`、`sparkles`、`coins`、`megaphone` |
| `state` | 返回卡片状态的**用户 GET 路由**，如 `/widget`，需要插件自己注册 |

每个插件最多 5 张卡片；字段无效时插件加载失败，管理端显示原因。卡片只在插件启用后显示，管理端插件详情的“用户端卡片”一栏列出插件注册的卡片。

JS 插件在脚本顶层调用：

```js
plugin.widget({ key: 'checkin', slot: 'dashboard', title: '每日签到', icon: 'gift', state: '/widget' });
```

Go 插件在 `Setup` 中调用：

```go
h.Widget(sdk.Widget{Key: "checkin", Slot: sdk.SlotDashboard, Title: "每日签到", Icon: sdk.IconCalendarCheck, State: "/widget"})
```

### 5.2 卡片状态与按钮

用户打开仪表盘时，用户端以当前用户身份请求 `{API 前缀}/plugin/{code}{state}`，路由返回卡片状态：

| 字段 | 说明 |
|------|------|
| `hidden` | 为 `true` 时不显示该卡片（如活动未开始） |
| `text` | 说明文字，最多 200 个字符 |
| `value` | 标题右侧醒目显示的数值，如 `+0.05`，最多 32 个字符 |
| `actions` | 按钮，最多 2 个：`label`（文字，最多 16 个字符）、`path`（点击时以 POST 请求的本插件用户路由）、`link`（点击时跳转到的用户端页面，如 `/plans`，设置后不请求 `path`）、`disabled`（禁用）、`confirm`（不为空时先弹出确认框） |

按钮设置 `link` 时只做页面跳转，用于“去选套餐”“查看邀请”等入口，`link` 只能是本站用户端页面路径（规则同 `path`）。

点击按钮时用户端以 POST 请求 `{API 前缀}/plugin/{code}{path}`：成功时若返回数据中有 `message` 字段则作为提示显示（否则显示“操作成功”），之后刷新该卡片和账户信息（余额等）；失败时（`plugin.fail` / `sdk.Fail`）显示错误信息。`state` 与 `path` 只能包含字母、数字、`_`、`-`、`/`，不能带路由参数（`:id`）。状态路由请求失败时该卡片不显示。

JS 示例（完整代码见 `examples/js-plugins/daily-bonus`）：

```js
plugin.route('user', 'GET', '/widget', function (req) {
  if (kv.get('done:' + req.user.id)) return { text: '今日已签到，明天再来', value: '+0.10' };
  return { text: '签到可获得 0.10 余额', actions: [{ label: '签到', path: '/checkin' }] };
});
plugin.route('user', 'POST', '/checkin', function (req) {
  // ……发放奖励
  return { message: '签到成功，余额 +0.10' };
});
```

Go 插件用 `sdk.WidgetState` 返回状态（示例见 `plugins/checkin`）：

```go
sdk.OK(c, sdk.WidgetState{Text: "签到可获得 0.10 余额", Actions: []sdk.WidgetAction{{Label: "签到", Path: "/checkin"}}})
```

只给部分用户显示的卡片，在状态路由中对不符合条件的用户返回 `hidden: true`（示例见 `plugins/firstorder`，购买过套餐的用户不显示首单优惠卡片）。

自制主题可通过 `GET {API 前缀}/user/plugin-widgets?slot=dashboard` 取得卡片列表并按上述规则显示（见接口参考“用户端”）。
