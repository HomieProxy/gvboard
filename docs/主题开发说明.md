# Gvboard 主题开发说明

主题只用于**不分离部署**（`server.mode: all`）的用户端页面。分离部署时用户端是独立的静态站点，不使用主题机制。

## 1. 安装与切换

- 主题放在服务器的主题目录下（配置项 `server.theme_dir`，默认是运行目录下的 `themes`），每个子目录是一个主题，目录名就是主题名（只能包含字母、数字、`_`、`-`）。
- 内置默认主题 `default` 编译在程序中；主题目录里如果有同名主题，以主题目录中的为准（可用来覆盖默认主题）。
- 主题目录每次访问时读取，放入或修改主题后不需要重启。多实例部署时每台服务器都要放同样的主题。
- 管理端“主题”页面可以查看主题列表、切换当前主题、修改主题配置。当前主题不存在或定义有误时，自动使用内置默认主题。
- 不提供上传主题包的功能。

## 2. 目录结构

```
themes/
└─ mytheme/
   ├─ theme.json      主题定义（必需）
   ├─ index.html      页面模板（必需）
   ├─ assets/         构建产物（文件名带内容哈希，浏览器长期缓存）
   └─ favicon.ico 等  其它静态文件
```

除 `theme.json`、`index.html` 和以 `.` 开头的文件 / 目录外，主题目录中的文件都从站点根路径访问，例如 `themes/mytheme/assets/index-3f2a.js` 的地址是 `/assets/index-3f2a.js`。所以页面中引用资源时用相对路径（`./assets/...`）或根路径（`/assets/...`），不要带主题名。

> 注意：主题目录中的文件都可以公开下载，不要放源码、密钥等文件。主题目录中的符号链接会被跟随，请不要指向主题目录以外的位置。

## 3. theme.json

格式与原 v2board 主题的 `config.json` 相同：

```json
{
  "name": "mytheme",
  "description": "我的主题",
  "version": "1.0.0",
  "images": "https://example.com/preview.png",
  "configs": [
    {
      "label": "主题色",
      "placeholder": "请选择主题颜色",
      "field_name": "theme_color",
      "field_type": "select",
      "select_options": { "default": "默认(蓝色)", "green": "奶绿色" },
      "default_value": "default"
    },
    { "label": "背景", "placeholder": "请输入背景图片URL", "field_name": "background_url", "field_type": "input" },
    { "label": "自定义页脚HTML", "field_name": "custom_html", "field_type": "textarea" }
  ]
}
```

| 字段 | 说明 |
|------|------|
| `name` / `description` / `version` / `images` | 管理端展示用，`images` 为预览图地址 |
| `configs` | 配置项定义，必须存在（可以是空数组） |
| `configs[].field_name` | 配置项名，字母、数字、`_`，不能重复 |
| `configs[].field_type` | `input`（单行）、`textarea`（多行）、`select`（下拉），省略时为 `input` |
| `configs[].select_options` | 下拉选项 `{"值": "显示文字"}`，`select` 必填 |
| `configs[].default_value` | 默认值，省略时为空字符串 |

定义有误（不是合法 JSON、缺少 `configs`、配置项名不合法或重复、类型不支持、下拉项没有选项、缺少 `index.html`）的主题不会出现在主题列表中，也不能切换过去。

配置值保存在数据库（设置表中名为 `theme_config.<主题名>` 的项），多实例共享，保存后立即生效。保存时只保留定义中的配置项，值只能是字符串、数字或布尔，下拉项必须是选项之一，单个值最长 64 KB。

## 4. index.html 与注入的配置

渲染用户端首页时，服务器对 `index.html` 做两处处理：

1. 把 `<title>` 的内容替换为站点名称；
2. 在 `</head>` 前插入站点描述 `<meta name="description">` 与配置脚本：

```html
<script>window.APP_CONFIG={...};</script>
```

`window.APP_CONFIG` 的内容：

```json
{
  "api": "/api/k3f9x2",
  "site": { "name": "站点名称", "description": "站点描述", "url": "https://example.com", "logo": "", "terms_url": "", "home": true },
  "register": { "closed": false, "email_code": false, "invite_required": false, "email_suffixes": [], "captcha_key": "" },
  "theme": { "id": "mytheme", "config": { "theme_color": "default", "background_url": "", "custom_html": "" } }
}
```

- `api`：原生 API 前缀，所有接口请求都以它开头。
- `site` / `register`：与分离部署时 `GET {api}/site` 返回的内容相同。`site.home` 为管理员是否开启了首页，主题没有首页时可以忽略。
- `theme.config`：当前主题的配置值（未保存过的项为默认值）。

本地开发时页面没有经过服务器渲染，读取不到 `window.APP_CONFIG`，可以只在开发环境中自行定义一个用于调试，不要带进构建产物。

`custom_html` 等自定义 HTML 由主题自行决定如何插入页面，这些内容由管理员填写，服务器不做过滤。

插件可以在仪表盘声明卡片（如签到）。主题如需显示，在仪表盘请求 `GET {api}/user/plugin-widgets?slot=dashboard`，按《接口参考 · 用户端》第 11.1 节的规则渲染；插件返回的文字必须以纯文本显示。不显示时插件的其它功能不受影响。

插件还可以给套餐加标签、在结账金额中加入调整明细（如首单优惠）：套餐接口的 `badges` 显示在套餐名称旁；结账页调用 `POST {api}/user/orders/preview` 取得金额明细与应付金额（参数同下单），按 `items` 逐行显示插件调整；订单详情的 `adjustments` 显示已保存的明细。见《接口参考 · 用户端》3.2、3.4.1、3.5 节。卡片按钮带 `link` 时只跳转到对应的用户端页面。

知识库文章与公告的正文是 HTML（插件也可能向文章插入内容）。主题显示正文时需支持复制按钮：点击带 `data-copy` 属性的元素（或其子元素）时阻止默认行为、复制该属性的值并提示结果，成功后给元素加上 `data-copied` 属性、1.5 秒后移除。内置主题把正文放在 Shadow DOM 中显示，脚本不会执行，主题的 CSS 变量（`--card`、`--border`、`--primary` 等）可以在正文中使用。

## 5. 路由

页面地址使用 `#` 形式（如 `/#/login`、`/#/dashboard`）。服务器只在根路径 `/` 返回页面，访问 `/login` 这类地址会得到 404。使用 Vue Router 时选择 `createWebHashHistory()`。

## 6. 使用 Vite 构建

```ts
// vite.config.ts
export default defineConfig({
  base: './',                  // 资源使用相对路径
  build: { outDir: 'dist', assetsDir: 'assets' },
})
```

构建后把 `dist/` 下的全部文件与 `theme.json` 放到 `themes/<主题名>/` 即可。

## 7. 去特征要求

站点不应能被识别为 v2board 或其衍生面板：

- 页面、脚本、样式中不要出现 `v2board`、`umi` 等字样，也不要沿用原项目的 `window.settings`、`/theme/default/assets` 这类路径与变量名；
- 不要请求原项目的接口路径（`/api/v1/guest/comm/config` 等），只使用 `api` 前缀下的原生接口。
