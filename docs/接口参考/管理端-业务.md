# 原生 API 接口参考：管理端业务部分

> 适用对象：管理端前端（Vue 3 + TypeScript + shadcn-vue）。
> 依据：`internal/{adminuser,order,node,payment,usercenter,httpx,auth,model}` 源码（以代码为准）。
> 范围：用户与订阅、套餐 / 优惠券 / 订单、节点、支付方式、礼品卡，共 **61** 个接口。

---

## 0. 通用约定

### 0.1 路径与鉴权

- 所有接口挂在 `{api}/{secure_path}` 下。`{api}` 为可配置的原生 API 前缀，`{secure_path}` 为系统设置项 `secure_path`。下文路径均**相对 `{api}/{secure_path}`**。
- 请求头：`Authorization: <登录返回的令牌>`（与用户端相同的解析方式）。
- 以下情况**一律返回 404 HTML 页面**（不是 JSON，状态码 404，`Content-Type: text/html`，内容与 nginx 默认 404 页面一致）：
  - `secure_path` 未设置或与路径不一致；
  - 未登录、令牌无效、当前用户不是管理员。
  
  前端不能依赖 JSON 解析 404，应按 HTTP 状态码判断，并把 404 当作“会话失效 / 无权限”处理（跳转登录）。

### 0.2 统一响应格式

```ts
interface ApiBody<T> {
  code: number   // 0 成功；失败时与 HTTP 状态码一致：400/401/403/404/409/422/429/500
  msg: string    // 成功为 "ok"；失败为错误文案（已按请求语言翻译）
  data?: T       // 成功时返回；失败时没有该字段
}
```

- 成功：HTTP 200，`code = 0`。
- 业务错误：HTTP 状态码 = `code`，例如参数错误 `422`、资源不存在 `404`、冲突 `409`、业务不允许 `400`。
- 内部错误：HTTP 500，`msg = "服务器内部错误"`。
- 请求体不是合法 JSON（或字段类型不匹配，例如数字字段传了字符串）：返回 422 参数错误（`Invalid parameters` 或 `参数有误`）。空请求体视为全部字段未传。
- 多数写操作成功时 `data = true`。

### 0.3 单位与格式约定（重要）

| 项目 | 约定 |
| --- | --- |
| 金额 | **分**（整数）。余额、佣金、套餐价格、订单金额、优惠券按金额的面值、礼品卡余额类面值、支付手续费固定部分均为分 |
| 时间 | **Unix 秒**（整数）。`created_at`、`updated_at`、`expired_at`、`paid_at`、`started_at`、`ended_at`、`last_login_at` 等 |
| 订阅流量 | **字节**（`transfer_enable`、`u`、`d`） |
| 套餐流量 | **GB**（`v2_plan.transfer_enable`）。套餐开通到订阅时乘以 1073741824 |
| 用户筛选里的流量 | **GB**（可为小数，服务端乘以 1073741824 后比较） |
| 限速 | `speed_limit`：Mbps，`null` 不限速 |
| 设备数 | `device_limit`：`null` 不限制 |
| 比例 | 折扣 `discount`、佣金比例 `commission_rate`、比例优惠券：0–100 的百分数 |
| 0/1 开关 | 统一用整数 `0` / `1` |

### 0.4 分页

本文涉及两种分页参数位置，返回结构相同：

```ts
interface PageResult<T> {
  data: T[]
  total: number
}
```

- 参数名：`current`（页码，从 1 开始，<1 按 1）与 `page_size`（每页条数，**最少 10、最多 100**，越界自动截断）。
- `users/query`、`orders/query`：参数放在 **JSON body** 中。
- `coupons`、`giftcards`：参数放在 **query string** 中。
- 注意：分页结果的字段名是 `data` 与 `total`，即完整响应为 `{ code, msg, data: { data: [...], total } }`。

### 0.5 文件下载接口

以下接口成功时**直接返回 CSV 文件**，不是 JSON：

| 接口 | 文件名 |
| --- | --- |
| `POST users/generate`（批量模式） | `users.csv` |
| `POST users/export` | `users.csv` |
| `POST coupons/batch` | `coupons.csv` |
| `POST giftcards/batch` | `giftcards.csv` |

- 响应头：`Content-Type: text/csv; charset=utf-8`，`Content-Disposition: attachment; filename="xxx.csv"`。
- 内容带 UTF-8 BOM，换行为 CRLF。
- 失败时仍返回 JSON 错误体（HTTP 状态码非 200）。
- 前端请求时应使用 `responseType: 'blob'`，然后根据 `Content-Type` 判断：是 `text/csv` 就触发下载；是 `application/json` 就把 blob 读成文本解析错误信息。

### 0.6 筛选条件格式（用户、订单共用）

```ts
interface Filter {
  key: string        // 筛选字段，必须在白名单内
  condition: '>' | '<' | '=' | '>=' | '<=' | '!=' | '模糊'
  value: string      // 一律传字符串
}
```

- `condition` 必须是上面 7 个字面值之一（`模糊` 为中文字面量，对应 SQL LIKE 包含匹配）。
- 多个条件之间是 **AND** 关系。
- 不在白名单内的字段、非法的条件、整数字段的值无法解析为整数，都会返回 422。
- 整数字段不支持 `模糊`。

## 1. 用户与订阅（`internal/adminuser`）

### 1.1 数据结构

```ts
/** 管理端账号字段（订阅数据见 AdminSub） */
interface AdminUser {
  id: number
  email: string
  balance: number                 // 余额，分
  commission_balance: number      // 佣金余额，分
  commission_type: 0 | 1 | 2      // 佣金类型：0 跟随系统设置，1 循环返利，2 首次返利
  commission_rate: number | null  // 专属佣金比例 0-100（%），null 使用系统设置
  discount: number | null         // 专属折扣 0-100（%），null 无
  banned: 0 | 1
  is_admin: 0 | 1
  is_staff: 0 | 1
  invite_user_id: number | null
  telegram_id: number | null
  remarks: string | null
  subscription_limit: number | null // 该用户订阅数量上限 0-1000，null 使用全局设置
  last_login_at: number | null    // Unix 秒
  created_at: number              // Unix 秒
  updated_at: number              // Unix 秒
}

/** 订阅原始字段（v2_subscription） */
interface Subscription {
  id: number
  user_id: number
  name: string                    // 订阅名称，最多 64 字符
  is_primary: 0 | 1               // 是否主订阅（每个用户恰好一个）
  plan_id: number | null          // null 表示未购买套餐
  group_id: number | null         // 权限组
  uuid: string
  token: string                   // 订阅链接令牌
  transfer_enable: number         // 总流量，字节
  u: number                       // 已用上行，字节
  d: number                       // 已用下行，字节
  t: number                       // 最后使用时间，Unix 秒（节点上报）
  device_limit: number | null     // 设备数限制，null 不限制
  speed_limit: number | null      // 限速 Mbps，null 不限速
  expired_at: number | null       // 到期时间 Unix 秒；null = 长期有效；0 或过去的时间 = 已到期
  auto_renewal: 0 | 1             // 自动续费
  remind_expire: 0 | 1            // 到期提醒邮件
  remind_traffic: 0 | 1           // 流量提醒邮件
  banned: 0 | 1                   // 订阅单独封禁
  bonus_traffic: number           // 本周期奖励流量，字节（已计入 transfer_enable，流量重置时扣回；如幸运大转盘的流量奖励）
  created_at: number
  updated_at: number
}

/** 管理端订阅（列表中使用） */
interface AdminSub extends Subscription {
  plan_name?: string              // 套餐名称；plan_id 为 null 时没有该字段
  alive_ip: number                // 当前在线设备（IP）数
  subscribe_url: string           // 订阅链接
}

/** 在线设备 */
interface AliveDevice {
  node: string                    // 节点类型 + 节点 ID，例如 "vmess3"
  ip: string
  update_at: number               // Unix 秒
}

/** 用户详情中的订阅 */
interface DetailSub extends AdminSub {
  devices: AliveDevice[]          // 各节点上的在线 IP
  share_ips: number               // 防分享窗口内拉取订阅的不同 IP 数（未启用防分享时为 0）
}

/** 用户列表的一行 */
interface UserListRow extends AdminUser {
  subscription_count: number      // 订阅数
  alive_ip: number                // 全部订阅在线设备数之和
  primary: AdminSub | null        // 主订阅摘要（没有订阅时为 null）
}

/** 用户详情 */
interface UserDetail extends AdminUser {
  invite_user: { id: number; email: string } | null
  subscriptions: DetailSub[]      // 主订阅在前，其余按 id 升序；没有订阅时为 []
}
```

### 1.2 用户筛选字段白名单（`filter[].key`）

“订阅字段”表示：用户的**任一订阅**满足条件即命中该用户。

| key | 含义 | 类型 | 说明 |
| --- | --- | --- | --- |
| `id` | 用户 ID | 整数 | |
| `email` | 邮箱 | 字符串 | 不区分大小写 |
| `invite_user_id` | 邀请人 ID | 整数 | |
| `invite_by_email` | 邀请人邮箱 | 字符串 | 不区分大小写，支持 `模糊` |
| `banned` | 账号封禁 | 整数 0/1 | |
| `remarks` | 备注 | 字符串 | |
| `is_admin` | 管理员 | 整数 0/1 | |
| `is_staff` | 客服 | 整数 0/1 | |
| `telegram_id` | Telegram ID | 整数 | |
| `balance` | 余额 | 整数（分） | |
| `commission_balance` | 佣金余额 | 整数（分） | |
| `transfer_enable` | 总流量 | 数字（**GB**，可小数） | 订阅字段 |
| `u` | 已用上行 | 数字（**GB**） | 订阅字段 |
| `d` | 已用下行 | 数字（**GB**） | 订阅字段 |
| `device_limit` | 设备数限制 | 整数 | 订阅字段 |
| `expired_at` | 到期时间 | 整数（Unix 秒） | 订阅字段 |
| `uuid` | UUID | 字符串 | 订阅字段 |
| `token` | 订阅令牌 | 字符串 | 订阅字段 |
| `plan_id` | 套餐 ID | 整数 | 订阅字段；`value: "null"` + `condition: "="` 表示“有未购买套餐的订阅” |
| `subscription_id` | 订阅 ID | 整数 | 订阅字段，按订阅 ID 找用户 |
| `subscription_banned` | 订阅封禁 | 整数 0/1 | 订阅字段 |

### 1.3 用户排序字段（`sort`）

`id`、`email`、`balance`、`commission_balance`、`banned`、`is_admin`、`is_staff`、`last_login_at`、`created_at`、`updated_at`。其他值按 `created_at`。`sort_type` 为 `ASC`（不区分大小写）时升序，其他值（含不传）降序。同值时按 `id` 同方向排序。

### 1.4 接口

#### POST `users/query` — 用户列表

Body：

```ts
interface UserQuery {
  current?: number      // 页码，默认 1
  page_size?: number    // 10-100
  sort?: string         // 见 1.3
  sort_type?: 'ASC' | 'DESC'
  filter?: Filter[]     // 见 1.2
}
```

响应 `data`：`PageResult<UserListRow>`。

错误：422 筛选字段 / 条件 / 值不合法。

#### POST `users/generate` — 生成用户

Body：

```ts
interface GenerateUsersInput {
  email_prefix?: string   // 不为空：只生成这一个用户（email = prefix@suffix）
  email_suffix: string    // 必填，邮箱域名部分（不含 @）
  password?: string       // 为空时密码与邮箱相同
  plan_id?: number        // 0 或不传：不开通套餐
  expired_at?: number | null // Unix 秒
  generate_count?: number // 批量模式（email_prefix 为空）时必填，1-500
}
```

- 每个生成的用户都带一个主订阅。
- `expired_at`：选择了套餐时，不传 / null 表示长期有效；没有选择套餐时，不传表示已到期（0）。
- **单个模式**（`email_prefix` 不为空）：成功返回 JSON，`data = true`。
- **批量模式**：成功直接返回 **CSV 文件 `users.csv`**，列为：`账号, 密码, 过期时间, UUID, 创建时间, 订阅地址`（时间格式 `YYYY-MM-DD HH:mm:ss`，长期有效显示“长期有效”）。随机前缀为 6 位小写字符。

错误：

| 状态 | msg | 场景 |
| --- | --- | --- |
| 422 | Invalid parameters | `email_suffix` 为空 |
| 422 | Email format is incorrect | 邮箱格式错误 |
| 409 | Email is already in use | 邮箱已存在 / 随机邮箱多次重试后仍冲突 |
| 400 | Subscription plan does not exist | 套餐不存在 |
| 422 | The number of users generated at a time is 1 to 500 | 批量数量越界 |

---

#### POST `users/export` — 导出用户 CSV

Body：`{ filter?: Filter[] }`（不传或空数组 = 导出全部用户）。

成功直接返回 **CSV 文件 `users.csv`**，**每个订阅一行**（没有订阅的用户不出现），列：

`邮箱, 余额(元), 推广佣金(元), 订阅 ID, 订阅名称, 主订阅(是/否), 总流量(GB), 设备数限制, 剩余流量(GB), 套餐到期时间, 订阅计划, 订阅地址`

注意 CSV 中金额已换算为**元**、流量为 **GB**；以 `= + - @` 等开头的单元格会被加单引号前缀（防公式注入）。

#### POST `users/mail` — 群发邮件

Body：

```ts
interface MailInput {
  filter?: Filter[]   // 不传 = 发给全部用户
  subject: string     // 必填
  content: string     // 必填，HTML，按管理员填写的原样输出到 notify 模板
}
```

响应 `data`：`{ count: number }`（投递到发送队列的邮件数）。

错误：422 `Subject and content cannot be empty`；422 筛选条件非法。

---

#### POST `users/ban` — 批量封禁

Body：`{ filter: Filter[] }`，**至少一个条件**。当前管理员自身会被自动排除。封禁后立即删除这些用户的全部登录会话。

响应 `data`：`{ count: number }`（封禁人数）。

错误：422 `Please set at least one filter condition`。

---

#### POST `users/batch-delete` — 批量删除

Body：`{ filter: Filter[] }`，**至少一个条件**；排除当前管理员。删除用户及其订阅、订单、邀请码、工单（含消息）、Telegram 偏好，并清空被其邀请用户的邀请人；佣金记录与流量统计保留。整个操作在一个事务中完成。

响应 `data`：`{ count: number }`（删除人数）。

错误：同 `users/ban`。

---

#### GET `users/:id` — 用户详情

响应 `data`：`UserDetail`（见 1.1，含全部订阅、每个订阅的在线设备与防分享 IP 数）。

错误：422 id 非正整数；404 `The user does not exist`。

---

#### PUT `users/:id` — 修改账号字段

Body（全部可选，**没有传的字段不修改**；标注“可 null”的字段传 `null` 表示清空）：

```ts
interface UpdateUserInput {
  email?: string                    // 校验格式，不区分大小写判重
  password?: string                 // 空字符串 = 不修改；否则至少 8 位
  balance?: number                  // 分
  balance_remark?: string           // 余额调整原因，最多 255 字符；只在 balance 有变化时写入余额变动日志
  commission_balance?: number       // 分
  commission_type?: 0 | 1 | 2
  commission_rate?: number | null   // 0-100，可 null
  discount?: number | null          // 0-100，可 null
  banned?: 0 | 1
  is_admin?: 0 | 1
  is_staff?: 0 | 1
  remarks?: string | null           // 可 null，最多 16383 字符
  subscription_limit?: number | null // 0-1000，可 null（使用全局设置）
  telegram_id?: null                // 只能传 null（解除 Telegram 绑定），传数字报 422
}
```

- 不能封禁自己、不能取消自己的管理员权限。
- 设置 `banned: 1` 时立即删除该用户全部登录会话。
- `balance` 与原余额不同时，在同一事务中写入一条类型为 `admin` 的余额变动日志（变动金额、操作管理员、`balance_remark`）。
- 订阅相关字段（套餐、流量、到期等）**不在这里改**，请用 `PUT subscriptions/:id`。

响应 `data`：`true`。

错误：

| 状态 | msg |
| --- | --- |
| 422 | Invalid parameters（开关不是 0/1、比例越界、commission_type 越界、subscription_limit 越界、telegram_id 非 null、remarks 过长） |
| 422 | 余额调整原因不能超过 255 个字 |
| 422 | Email format is incorrect |
| 422 | Password must be greater than 8 digits |
| 409 | Email is already in use |
| 400 | You cannot ban, delete or remove the admin permission of your own account |
| 404 | The user does not exist |

#### DELETE `users/:id` — 删除用户

删除范围同批量删除；删除后注销该用户全部会话。不能删除自己。

响应 `data`：`true`。错误：400 不能删除自己；404 用户不存在。

---

#### POST `users/:id/inviter` — 设置 / 清除邀请人

Body：`{ invite_user_email: string }`，空字符串（或不传）= 清除邀请人。

邀请人不能是用户自己，也不能是该用户邀请链下游的用户（防止循环）。

响应 `data`：`true`。

错误：404 用户不存在；400 `The inviter does not exist`；400 `The inviter cannot be the user or one of the users invited by the user`。

#### GET `users/:id/balance-logs` — 余额变动日志

Query：`type`（可选，按类型筛选）、`current`（默认 1）、`page_size`（10～100，默认 10）。按时间倒序。

所有修改用户余额的业务（下单抵扣、取消退回、充值、礼品卡、佣金、管理员修改、插件等）都会在同一事务中写入一条日志；超过系统配置 `balance_log_retention_days` 天数的日志由每日清理任务删除，删除用户时一并删除。

响应 `data`：

```ts
interface BalanceLogPage {
  data: {
    id: number
    user_id: number
    amount: number          // 变动金额（分），正数增加、负数减少
    balance: number         // 变动后余额（分）
    type: 'order_pay' | 'order_cancel' | 'order_restore' | 'renewal' | 'deposit' | 'plan_refund'
        | 'giftcard' | 'commission' | 'transfer' | 'admin' | 'plugin'
    trade_no: string        // 关联订单号，没有时为空字符串
    operator_id: number | null // 操作管理员（admin 与补单）
    operator_email: string  // 管理员已删除时为空
    plugin: string          // 插件标识（plugin 类型）
    remark: string          // 备注：管理员填写的原因、插件备注、充值赠送金额、礼品卡卡密等
    created_at: number
    email: string           // 用户邮箱
  }[]
  total: number
  income: number            // 筛选范围内增加金额合计（分）
  expense: number           // 筛选范围内减少金额合计（分，负数）
}
```

#### GET `balance-logs` — 全站余额变动日志

Query：在 `users/:id/balance-logs` 的参数基础上增加 `email`（用户邮箱，模糊匹配）、`since`、`until`（Unix 秒，含两端；`since` 晚于 `until` 时返回 400）。响应结构同上，按时间倒序。

```ts
// 示例：查询某段时间内某邮箱的礼品卡入账
GET balance-logs?email=example.com&type=giftcard&since=1767196800&until=1769875199
```

| type | 说明 |
| --- | --- |
| order_pay | 下单时余额抵扣 |
| order_cancel | 取消待支付订单（含超时自动取消）退回抵扣 |
| order_restore | 已取消订单补单时重新扣回抵扣 |
| renewal | 余额自动续费 |
| deposit | 充值到账（含充值赠送） |
| plan_refund | 更换套餐时旧订阅剩余价值超过新套餐价格的差额退回 |
| giftcard | 兑换金额礼品卡 |
| commission | 关闭提现时邀请佣金直接进入余额 |
| transfer | 佣金转余额 |
| admin | 管理员修改 |
| plugin | 插件调整 |

错误：422 `Invalid parameters`（未知类型）；404 用户不存在。

#### 订阅参数 `SubInput`（新开、修改订阅共用）

```ts
interface SubInput {
  name?: string                 // 最多 64 字符（自动去首尾空白）
  plan_id?: number | null       // 传 null = 清空套餐，同时清空权限组；传 ID 时权限组同步为套餐的权限组
  transfer_enable?: number      // 总流量，字节，>= 0
  u?: number                    // 已用上行，字节，>= 0
  d?: number                    // 已用下行，字节，>= 0
  device_limit?: number | null  // >= 0；null = 不限制
  speed_limit?: number | null   // Mbps，>= 0；null = 不限速
  expired_at?: number | null    // Unix 秒，>= 0；null = 长期有效
  banned?: 0 | 1
  auto_renewal?: 0 | 1
  remind_expire?: 0 | 1
  remind_traffic?: 0 | 1
}
```

没有传的字段不修改。注意流量单位为**字节**（与套餐的 GB 不同）。传 `transfer_enable` 时同时清零本周期奖励流量 `bonus_traffic`。

#### POST `users/:id/subscriptions` — 为用户新开订阅

Body：`SubInput`。

- 不受用户订阅数量上限限制。
- 选择了套餐时，先按套餐设置权限组、流量（GB×1073741824）、设备数、限速，再用请求中的其余字段覆盖。
- `expired_at` 不传 = 长期有效。
- 新订阅不是主订阅。

响应 `data`：`Subscription`（原始订阅字段，**不含** `plan_name`、`alive_ip`、`subscribe_url`）。

错误：404 用户不存在；422 参数非法；400 `Subscription plan does not exist`。

#### PUT `subscriptions/:id` — 修改订阅

Body：`SubInput`。响应 `data`：`true`。

错误：404 `The subscription does not exist`；422 参数非法；400 套餐不存在。

#### DELETE `subscriptions/:id` — 删除订阅

- 主订阅不能删除（400 `The primary subscription cannot be deleted`）。
- 该订阅有待支付（0）或开通中（1）的订单时不能删除（400 `The subscription has unfinished orders`）。

响应 `data`：`true`。错误另有 404 订阅不存在。

#### POST `subscriptions/:id/reset-security` — 重置 UUID 与订阅令牌

无 Body。重置后旧订阅链接立即失效。响应 `data`：`true`。错误：404 订阅不存在。

#### POST `subscriptions/:id/primary` — 设为主订阅

无 Body。同一用户的其他订阅自动取消主订阅。响应 `data`：`true`。错误：404 订阅不存在 / 用户不存在。

### 2.1 付款周期（period）

### 2.2 套餐

```ts
interface Plan {
  id: number
  group_id: number                  // 权限组 ID
  transfer_enable: number           // 流量，**GB**
  device_limit: number | null       // 设备数限制，null 不限制
  name: string
  speed_limit: number | null        // Mbps，null 不限速
  show: 0 | 1                       // 是否销售（用户端可见）
  sort: number | null               // 排序值，升序
  renew: 0 | 1                      // 是否允许续费
  content: string | null            // 套餐描述（HTML/Markdown，由主题决定）
  // 各周期价格，单位**分**；null 表示该周期不开放
  month_price: number | null
  quarter_price: number | null
  half_year_price: number | null
  year_price: number | null
  two_year_price: number | null
  three_year_price: number | null
  onetime_price: number | null
  reset_price: number | null        // 流量重置包价格
  reset_traffic_method: 0 | 1 | 2 | 3 | 4 | null
    // 流量重置方式：0 每月 1 日；1 按到期日每月重置；2 不重置；3 每年 1 月 1 日；4 按到期日每年重置；null 跟随系统设置
  capacity_limit: number | null     // 最大有效订阅数（容量），null 不限制
  created_at: number
  updated_at: number
}

interface AdminPlan extends Plan {
  count: number   // 正在使用该套餐的有效订阅数（未到期或长期有效）
}
```

#### GET `plans` — 套餐列表

无参数，不分页。按 `sort` 升序、`id` 升序。响应 `data`：`AdminPlan[]`。

#### POST `plans` — 新建套餐 / PUT `plans/:id` — 修改套餐

Body：

```ts
interface PlanInput {
  name: string                      // 必填（去首尾空白后不能为空）
  group_id: number                  // 必填
  transfer_enable: number           // 必填，GB
  content?: string | null
  device_limit?: number | null
  speed_limit?: number | null
  capacity_limit?: number | null
  reset_traffic_method?: 0 | 1 | 2 | 3 | 4 | null
  month_price?: number | null       // 分；以下价格字段同理，null 或不传 = 不开放该周期
  quarter_price?: number | null
  half_year_price?: number | null
  year_price?: number | null
  two_year_price?: number | null
  three_year_price?: number | null
  onetime_price?: number | null
  reset_price?: number | null
  force_update?: boolean            // 仅修改时有效：把权限组、流量、设备数、限速同步到正在使用该套餐的全部订阅
}
```

- **修改是整体覆盖**：上面除 `force_update` 外的全部字段都会写入，不传的可空字段会被写成 `null`（即关闭对应周期价格）。前端应把编辑表单的完整数据一起提交。
- 新建的套餐默认 `show = 0`（不销售）、`renew = 1`（允许续费）。`show` / `renew` / `sort` 不能通过此接口修改。
- Body 中的 `id` 会被忽略（以路径为准）。

响应 `data`：`true`。

错误：422 `参数有误`（name 为空、缺 group_id / transfer_enable、reset_traffic_method 越界）；404 `该订阅不存在`（修改时套餐不存在）。

#### PATCH `plans/:id` — 销售 / 续费开关

Body：`{ show?: 0 | 1, renew?: 0 | 1 }`，未传的项不修改。

响应 `data`：`true`。错误：422 值不是 0/1；404 套餐不存在。

#### DELETE `plans/:id` — 删除套餐

存在相关订单（409 `该订阅下存在订单无法删除`）或有订阅使用（409 `该订阅下存在用户无法删除`）时不能删除。

响应 `data`：`true`。错误另有 404 套餐不存在。

#### POST `plans/sort` — 套餐排序

Body：`{ ids: number[] }`，按数组顺序把 `sort` 设为 1..n。任一 ID 不存在则整体回滚并返回 404。

响应 `data`：`true`。

#### GET `coupons` — 优惠券列表

Query：`current`、`page_size`、`sort`、`sort_type`。

响应 `data`：`PageResult<Coupon>`。

#### POST `coupons` — 新建 / PUT `coupons/:id` — 修改

Body：

```ts
interface CouponInput {
  name: string                      // 必填
  type: 1 | 2                       // 必填
  value: number                     // 见 Coupon.value（服务端不校验范围，前端应限制比例 1-100）
  started_at: number                // 必填，> 0，Unix 秒
  ended_at: number                  // 必填，> 0，Unix 秒
```

#### POST `coupons/batch` — 批量生成

#### POST `coupons/:id/toggle` — 切换启用状态

无 Body，`show` 取反。响应 `data`：`true`。错误：404 `优惠券不存在`。

#### DELETE `coupons/:id` — 删除

响应 `data`：`true`。错误：404 `优惠券不存在`。

### 2.4 订单

```ts
/** 订单类型 */
type OrderType = 1 | 2 | 3 | 4 | 9   // 1 新购；2 续费；3 升级（变更套餐）；4 流量重置包；9 充值
/** 订单状态 */
type OrderStatus = 0 | 1 | 2 | 3 | 4 // 0 待支付；1 开通中；2 已取消；3 已完成；4 已折抵
/** 佣金状态 */
type CommissionStatus = 0 | 1 | 2 | 3 // 0 待确认；1 发放中；2 有效（已发放）；3 无效

interface Order {
  id: number
  invite_user_id: number | null       // 获得佣金的邀请人
  user_id: number
  plan_id: number                     // 充值订单为 0
  coupon_id: number | null
  payment_id: number | null
  type: OrderType
  period: string                      // 见 2.1
  trade_no: string                    // 订单号
  callback_no: string | null          // 支付平台流水号；手动标记支付时为 "manual_operation"
  total_amount: number                // 应付金额，分
  handling_amount: number | null      // 手续费，分
  discount_amount: number | null      // 优惠金额，分
  surplus_amount: number | null       // 折抵金额（旧订阅剩余价值），分
  refund_amount: number | null        // 退款金额，分
  balance_amount: number | null       // 使用余额，分
  surplus_order_ids: number[] | null  // 被折抵的订单 ID
  status: OrderStatus
  commission_status: CommissionStatus
  commission_balance: number          // 佣金，分
  actual_commission_balance: number | null // 实际发放佣金，分
  paid_at: number | null              // Unix 秒
  subscription_id: number | null      // 作用的订阅；新开订阅的订单在开通后回填
  immediate: 0 | 1                    // 同套餐续费是否立刻生效，1 时详情显示“立即生效”
  created_at: number
  updated_at: number
}

interface AdminOrder extends Order {
  plan_name?: string                  // 套餐名；充值订单或套餐已删除时没有该字段
  email: string                       // 用户邮箱；用户已删除时为 ""
  subscription_name?: string          // 关联订阅的名称，订阅未命名时为其当前套餐名；无关联订阅或订阅已删除时没有该字段
}

interface CommissionLog {
  id: number
  invite_user_id: number
  user_id: number
  trade_no: string
  order_amount: number                // 分
  get_amount: number                  // 分
  created_at: number
  updated_at: number
}

interface AdminOrderDetail extends AdminOrder {   // 与列表一样带 plan_name、email、subscription_name
  commission_log: CommissionLog[]     // 无记录时 []
  surplus_orders: Order[]             // 被折抵的订单，无则 []
}
```

#### POST `orders/query` — 订单列表

Body：

```ts
interface OrderQuery {
  current?: number
  page_size?: number                  // 10-100
  is_commission?: boolean             // true：只看有佣金的订单（有邀请人、状态不是待支付/已取消、佣金 > 0）
  filter?: Filter[]
}
```

筛选字段白名单：

| key | 类型 | 说明 |
| --- | --- | --- |
| `email` | 字符串 | 按用户邮箱**包含匹配**（不区分大小写），无论 condition 填什么都按模糊匹配 |
| `trade_no` | 字符串 | |
| `callback_no` | 字符串 | |
| `status` | 整数 | 见 OrderStatus |
| `commission_status` | 整数 | 见 CommissionStatus |
| `user_id` | 整数 | |
| `invite_user_id` | 整数 | |
| `commission_balance` | 整数（分） | |
| `subscription_id` | 整数 | |
| `plan_id` | 整数 | |

- 排序固定为 `created_at` 降序、`id` 降序，不支持自定义排序。

响应 `data`：`PageResult<AdminOrder>`。错误：422 筛选非法。

#### POST `orders/assign` — 手动分配订单

Body：

```ts
interface AssignInput {
  email: string             // 必填，用户邮箱（不区分大小写）
  plan_id: number           // 必填，非 0
  period: string            // 必填，见 2.1，不能是 deposit
  total_amount: number      // 必填，>= 0，分
  subscription_id?: number  // 0 或不传：新开订阅；流量重置包（reset_price）必须指定
}
```

- 创建的是**待支付**订单，订单类型自动判断（重置包 / 升级 / 续费 / 新购），不计算折抵；不受订阅数量上限限制。
- 若想直接开通，再调用 `orders/:trade_no/paid`。

响应 `data`：`string`（订单号 trade_no）。

错误：

| 状态 | msg |
| --- | --- |
| 422 | 参数有误 |
| 422 | 购买流量重置包必须指定订阅 |
| 404 | 该用户不存在 |
| 404 | 该订阅不存在（套餐不存在） |
| 409 | 该用户还有待支付的订单，无法分配 |
| 404/400 | 订阅不属于该用户（来自订阅服务的错误） |

#### GET `orders/:trade_no` — 订单详情

响应 `data`：`AdminOrderDetail`。错误：404 `订单不存在`。

#### POST `orders/:trade_no/paid` — 标记已支付

只能操作待支付订单。成功后按正常支付流程开通（`callback_no = "manual_operation"`）。

响应 `data`：`true`。错误：404 `订单不存在`；400 `只能对待支付的订单进行操作`。

#### POST `orders/:trade_no/cancel` — 取消订单

只能取消待支付订单（会退回已抵扣的余额等）。

响应 `data`：`true`。错误：404；400 `只能对待支付的订单进行操作`。

#### POST `orders/:trade_no/restore` — 已取消订单补单

用于支付方掉单（订单取消后才收到付款）。Body 可省略：`{ callback_no?: string }`（支付方单号，≤ 255 字符，留空记为 `manual_restore`）。

- 只能操作**已取消**订单。订单改为已支付（`paid_at` 为当前时间），之后按正常支付流程开通，并触发插件的订单支付事件。
- 下单时使用了余额抵扣（`balance_amount > 0`）的，取消时已退回，补单时**重新扣回**；用户余额不足时拒绝补单，订单与余额都不变。
- 已取消订单收到支付回调时系统不会自动处理，只发 Telegram 告警提醒管理员调用本接口。

响应 `data`：`true`。错误：404 `订单不存在`；400 `只能对已取消的订单补单`；400 `用户余额不足以扣回下单时抵扣的余额，无法补单`；422 参数有误。

#### PUT `orders/:trade_no` — 修改佣金状态

Body：`{ commission_status: 0 | 1 | 3 }`（必填；只允许 0 待确认、1 发放中、3 无效；**不允许直接设为 2**）。

响应 `data`：`true`。错误：422 `参数有误`；404 `订单不存在`。

### 3.4 节点总览

#### GET `servers` — 全部节点

无参数，不分页。返回全部 8 类节点合并后的数组，按 `sort` 升序（`sort` 为 null 的在最前，同值保持类型顺序 shadowsocks、vmess、trojan、tuic、hysteria、vless、anytls、v2node，同类型按 id）。

每一项 = 该类型节点的全部字段（见 3.6 / 3.7）+ 以下附加字段：

```ts
interface ServerOverviewExtra {
  type: ServerType
  online: number | null           // 在线用户数（子节点取父节点的值）
  last_check_at: number | null    // 最后一次拉取配置时间，Unix 秒
  last_push_at: number | null     // 最后一次上报流量时间，Unix 秒
  available_status: 0 | 1 | 2     // 0 离线（5 分钟内未拉取）；1 在线但 5 分钟内无流量上报；2 正常
  install_command?: string        // 仅 v2node：一键安装命令
}
```

注意：`anytls` 与 `v2node` 的 `padding_scheme` 在总览中以 **JSON 文本字符串** 返回（与保存时提交的格式一致）。

#### POST `servers/sort` — 批量排序

Body：`{ [type: string]: { [id: string]: number } }`，例如：

```json
{ "vmess": { "3": 1, "5": 2 }, "trojan": { "1": 3 } }
```

在一个事务中写入；任一类型非法（404 `节点类型不存在`）、ID 非法（422）或节点不存在（400 `保存失败`）则全部不生效。响应 `data`：`true`。

### 3.5 节点保存与操作

#### POST `servers/:type` — 新建节点 / PUT `servers/:type/:id` — 修改节点

- Body 为 JSON 对象，**字段名与数据库列名一致**（见 3.6 / 3.7；注意 vmess 部分字段为驼峰）。请求体上限 1 MB。
- 处理规则（与原项目 Laravel 一致）：所有层级的字符串去首尾空白，**空字符串视为 null**；数字可以传数字或数字字符串；0/1 开关可传 `0`/`1`/`"0"`/`"1"`。
- **修改时同样要通过完整校验**：通用必填字段（`name`、`group_id`、`host`、`port`、`server_port`、`rate`）以及类型专有必填字段每次都必须提交。修改只写入请求中出现的字段（以及服务端补全的字段）。
- 新建的节点 `show` 取请求值（不传为 0）。
- 响应 `data`：`true`。
- 错误：404 `节点类型不存在`；422 具体校验文案（见各字段）或 `参数有误`；404 `服务器不存在`（修改时）；400 `创建失败` / `保存失败`。

#### DELETE `servers/:type/:id` — 删除节点

响应 `data`：`true`。错误：404 `节点类型不存在` / `节点ID不存在`。

#### POST `servers/:type/:id/show` — 显示 / 隐藏

Body：`{ show: 0 | 1 }`（必填）。响应 `data`：`true`。错误：422 `显示状态格式不正确`；404 `该服务器不存在`。

#### POST `servers/:type/:id/copy` — 复制节点

无 Body。新节点为隐藏状态（`show = 0`），其余字段（**包括 `created_at`**）与原节点相同。注意：Shadowsocks 2022 的服务端密钥由 `created_at` 派生，复制出的节点与原节点密钥相同。

响应 `data`：`true`。错误：404 `服务器不存在`；400 `复制失败`。

### 3.6 通用字段（全部类型）

```ts
interface ServerBase {
  id: number
  group_id: number[]          // 权限组 ID 数组
  route_id: number[] | null   // 路由规则 ID 数组
  name: string
  parent_id: number | null    // 父节点 ID（子节点共享父节点的在线状态）
  host: string                // 连接地址
  port: string                // 连接端口（字符串，可为端口段，如 "10000-20000"）
  server_port: number         // 后端服务监听端口
  tags: string[] | null
  rate: string                // 倍率（字符串形式的数字，如 "1"、"0.5"）
  show: 0 | 1
  sort: number | null
  created_at: number
  updated_at: number
}
```

保存时的校验：

| 字段 | 必填 | 校验 / 错误文案 |
| --- | --- | --- |
| `name` | 是 | 节点名称不能为空 |
| `group_id` | 是（非空数组） | 权限组不能为空；必须是整数数组：权限组格式不正确 |
| `route_id` | 否 | 若提交必须是整数数组：路由组格式不正确 |
| `parent_id` | 否 | 整数：父节点格式不正确 |
| `host` | 是 | 节点地址不能为空 |
| `port` | 是 | 连接端口不能为空（字符串或数字均可，保存为字符串） |
| `server_port` | 是 | 整数：后端服务端口不能为空 / 格式不正确 |
| `tags` | 否 | 数组：标签格式不正确 |
| `rate` | 是 | 数字：倍率不能为空 / 格式不正确（保存为字符串） |
| `show` | 否 | 0/1：显示状态格式不正确 |
| `sort` | 否 | 整数：排序格式不正确 |

### 3.7 各类型专有字段

以下“对象”字段（`*_settings`、`networkSettings` 等）后端只校验“是对象或数组或 null”，内部结构原样保存为 JSON 并下发给节点 / 生成订阅。表中列出的常用子键来自订阅生成代码，供表单设计参考。

#### shadowsocks

```ts
interface ServerShadowsocks extends ServerBase {
  cipher: string               // 必填
  obfs: 'http' | null
  obfs_settings: { host?: string; path?: string } | null
}
```

- `cipher` 可选值：`aes-128-gcm`、`aes-192-gcm`、`aes-256-gcm`、`chacha20-ietf-poly1305`、`2022-blake3-aes-128-gcm`、`2022-blake3-aes-256-gcm`（错误：加密方式不能为空 / 加密方式格式不正确）。
- `obfs` 只能是 `http` 或 null（混淆格式不正确）。

#### vmess（注意：对象字段名为驼峰）

```ts
interface ServerVmess extends ServerBase {
  tls: number                  // 必填整数：0 关闭，1 开启
  network: 'tcp' | 'kcp' | 'ws' | 'http' | 'domainsocket' | 'quic' | 'grpc' | 'httpupgrade' | 'xhttp' // 必填
  networkSettings: Record<string, any> | null
  tlsSettings: { serverName?: string; allowInsecure?: 0 | 1 } | null
  ruleSettings: Record<string, any> | null
  dnsSettings: Record<string, any> | null
  rules: string | null         // 只读（历史字段，不可通过保存修改）
}
```

- `networkSettings.security` 若提交，只能是 `auto`、`aes-128-gcm`、`chacha20-poly1305`、`none`。
- `networkSettings` 常用子键（按 network）：
  - `tcp`：`header.type`（`http` 时 `header.request.headers.Host[]`、`header.request.path[]`）
  - `ws`：`path`、`headers.Host`
  - `grpc`：`serviceName`
  - `kcp`：`seed`、`header.type`
  - `httpupgrade`：`path`、`host`
  - `xhttp`：`path`、`host`、`mode`（默认 `auto`）、`extra`（对象）

#### trojan

```ts
interface ServerTrojan extends ServerBase {
  network: string | null       // 必填（如 tcp / ws / grpc）
  network_settings: Record<string, any> | null // ws：path、headers.Host；grpc：serviceName
  allow_insecure: 0 | 1
  server_name: string | null   // SNI
}
```

错误：传输协议不能为空 / 传输协议配置有误 / 允许不安全格式不正确。

#### tuic

```ts
interface ServerTuic extends ServerBase {
  server_name: string | null
  insecure: 0 | 1                // 必填
  disable_sni: 0 | 1             // 必填
  zero_rtt_handshake: 0 | 1      // 必填
  udp_relay_mode: string | null  // 常用 native / quic（后端不校验）
  congestion_control: string | null // 常用 bbr / cubic / new_reno（后端不校验）
}
```

错误：`insecure 格式不正确` 等（`<字段名> 格式不正确`）。

#### hysteria

```ts
interface ServerHysteria extends ServerBase {
  version: 1 | 2                 // 必填
  up_mbps: number                // 数字，不传为 0
  down_mbps: number              // 数字，不传为 0
  obfs: string | null            // 混淆类型（v2 常用 salamander），null 关闭
  obfs_password: string | null   // 开启混淆且未填时自动生成 16 位；关闭混淆时清空
  server_name: string | null
  insecure: 0 | 1                // 必填
}
```

错误：版本格式不正确 / 带宽格式不正确 / `insecure 格式不正确`。

#### vless

```ts
interface ServerVless extends ServerBase {
  tls: 0 | 1 | 2                 // 必填：0 无，1 TLS，2 REALITY
  tls_settings: VlessTlsSettings | null
  flow: 'xtls-rprx-vision' | null // network 不是 tcp 时自动清空
  network: string                // 必填（tcp / ws / grpc / httpupgrade / xhttp 等，后端不校验枚举）
  network_settings: Record<string, any> | null // 子键同 vmess 的 networkSettings
  encryption: string | null      // 常用 none / mlkem768x25519plus
  encryption_settings: VlessEncryptionSettings | null
}

interface VlessTlsSettings {
  server_name?: string           // SNI（REALITY 时为伪装目标域名）
  allow_insecure?: 0 | 1
  fingerprint?: string           // 默认 chrome
  // tls = 2（REALITY）时，以下未填写会自动补全：
  private_key?: string           // 未填自动生成 x25519 私钥
  public_key?: string            // 未填时由私钥推导
  short_id?: string              // 未填时取私钥 SHA1 前 8 位
  server_port?: string           // 目标端口，未填为 "443"
}

interface VlessEncryptionSettings {
  mode?: string                  // 如 native
  rtt?: '0rtt' | '1rtt'          // 1rtt 时 ticket 自动设为 "0s"
  ticket?: string
  client_padding?: string
  private_key?: string           // encryption = mlkem768x25519plus 时未填自动生成
  password?: string              // 未填时为私钥对应公钥
}
```

错误：TLS格式不正确 / tls配置有误 / 流控格式不正确 / 传输协议不能为空 / 传输协议配置有误 / 加密配置有误。

`network = xhttp` 时，`network_settings.extra` 中的 `noGRPCHeader`、`noSSEHeader` 会转为布尔，`scMaxBufferedPosts`、`xmux.hKeepAlivePeriod`、`downloadSettings.port` 会转为整数。

#### anytls

```ts
interface ServerAnytls extends ServerBase {
  server_name: string | null
  insecure: 0 | 1                // 必填
  padding_scheme: string | null  // 提交时传 JSON 文本（如 "[\"stop=8\",...]"）；不是合法 JSON 时保存为 null。总览中也以 JSON 文本返回
}
```

#### v2node（多协议）

```ts
interface ServerV2node extends ServerBase {
  listen_ip: string              // 为空时保存为 "0.0.0.0"
  protocol: 'shadowsocks' | 'vmess' | 'vless' | 'trojan' | 'tuic' | 'hysteria2' | 'anytls' // 必填
  tls: 0 | 1 | 2                 // 必填：0 无，1 TLS，2 REALITY
  tls_settings: V2nodeTlsSettings | null
  flow: 'xtls-rprx-vision' | null
  network: 'tcp' | 'ws' | 'grpc' | 'http' | 'httpupgrade' | 'xhttp' // 必填
  network_settings: Record<string, any> | null // acceptProxyProtocol 会转为布尔
  trusted_x_forwarded_for: any[] | Record<string, any> | null
  encryption: string | null      // 如 mlkem768x25519plus
  encryption_settings: VlessEncryptionSettings | null // mlkem 时额外默认 mode=native、rtt=0rtt、ticket=600s
  disable_sni: 0 | 1             // 必填
  zero_rtt_handshake: 0 | 1      // 必填
  udp_relay_mode: string | null  // tuic 用
  congestion_control: string | null // tuic 用
  cipher: string | null          // shadowsocks 用，未填默认 aes-128-gcm
  up_mbps: number                // hysteria2 用，不传为 0
  down_mbps: number
  obfs: string | null            // hysteria2 用
  obfs_password: string | null   // 开启混淆且未填时自动生成 16 位
  padding_scheme: string | null  // anytls 用，规则同 anytls（JSON 文本）
}

interface V2nodeTlsSettings extends VlessTlsSettings {
  ech?: '' | 'cloudflare' | 'custom'
  ech_server_name?: string       // ech = custom 时必须填写，否则 ech 被置空
  ech_key?: string               // ech = custom 且未填时自动生成
  ech_config?: string            // 同上
  cert_mode?: string             // 为 remote 且 tls = 1 时：未提供证书则沿用已保存证书，没有则自动生成自签名证书
  tls_cert?: string
  tls_key?: string
  pinned_peer_cert_sha256?: string // 自签名证书指纹（自动生成）
}
```

v2node 自动规则：

- `protocol` 为 `trojan`、`tuic`、`hysteria2` 时 `tls` 强制为 1；`anytls` 且 `tls = 0` 时改为 1。
- `tls = 2` 时按 VLESS REALITY 规则补全密钥。
- `network` 不是 tcp、且 `encryption` 不为空也不是 `mlkem768x25519plus` 时清空 `flow`。

错误：协议格式不正确 / TLS格式不正确 / tls配置有误 / 流控格式不正确 / 传输协议格式不正确 / 传输协议配置有误 / 信任的转发头格式不正确 / 加密配置有误 / 带宽格式不正确 / `disable_sni 格式不正确` 等。

## 4. 支付方式（`internal/payment`）

### 4.1 数据结构

```ts
interface AdminPayment {
  id: number
  uuid: string                       // 8 位随机，用于回调地址
  payment: string                    // 网关名，见 payments/gateways
  name: string                       // 显示名称
  icon: string | null                // 图标 URL
  config: Record<string, any> | null // 网关配置（明文，包含密钥）
  notify_domain: string | null       // 自定义回调域名（协议 + 主机）
  handling_fee_fixed: number | null  // 固定手续费，分
  handling_fee_percent: number | null // 百分比手续费，0.1-100（%）
  enable: 0 | 1
  sort: number | null
  created_at: number
  updated_at: number
  notify_url: string                 // 回调地址：(notify_domain 或当前站点地址) + {api}/payment/notify/{payment}/{uuid}
}
```

手续费计算：`round(订单金额 × percent / 100 + fixed)`（分）。

### 4.2 接口

#### GET `payments/gateways` — 可用网关名称

响应 `data`：`string[]`。内置网关：`AlipayF2F`、`BEasyPaymentUSDT`、`BTCPay`、`Coinbase`、`CoinPayments`、`EPay`、`EPay2`、`EPayQrcode`、`EPaySubmitQrcode`、`Epusdt`、`Paytaro`、`PaytaroQR`、`StripeALL`、`StripeAlipay`、`StripeCheckout`、`StripeCredit`、`StripeWepay`、`TokenPay`、`WechatPayNative`，以及已启用插件注册的网关。排序：名称含 `Paytaro` 的排最前，其余按字典序。旧名称 `QrcodeEpay` 与 `EPayQrcode` 相同，不在列表中；已使用该名称的支付方式仍可下单、回调与编辑。

#### GET `payments` — 支付方式列表

无参数，不分页。按 `sort` 升序（null 在前）、`id` 升序。响应 `data`：`AdminPayment[]`。

#### GET `payments/form` — 网关配置表单

Query：`payment`（必填，网关名）、`id`（可选，支付方式 ID；传入时用该支付方式的现有配置填充 `value`）。

响应 `data`：**有序对象**（键顺序即表单显示顺序），键为配置项名：

```ts
type PaymentForm = Record<string, PaymentFormField>

type PaymentFormField =
  | { type: 'input'; label: string; description: string; value?: any }
  | { type: 'alert'; content: string; value?: any }   // 只展示 content（HTML），不是输入项，不要提交
```

示例（EPay）：

```json
{
  "url":  { "type": "input", "label": "URL",  "description": "" },
  "pid":  { "type": "input", "label": "PID",  "description": "" },
  "key":  { "type": "input", "label": "KEY",  "description": "" },
  "type": { "type": "input", "label": "TYPE", "description": "支付类型，如: alipay, wxpay, qqpay" }
}
```

- 没有 `value` 字段表示未配置。
- 遍历时请使用 `Object.keys()` 保持顺序（JSON 对象键顺序由后端保证）。

错误：400 `gate is not found`（网关不存在或插件已停用）；422 id 非法；404 `支付方式不存在`。

#### POST `payments` — 新建 / PUT `payments/:id` — 修改

Body：

```ts
interface PaymentSaveInput {
  name: string                         // 必填
  payment: string                      // 必填，网关名
  config: Record<string, any>          // 必填，非空对象；键为表单中 type=input 的项
  icon?: string | null
  notify_domain?: string | null        // 必须是合法 URL（如 https://pay.example.com）
  handling_fee_fixed?: number | null   // 分
  handling_fee_percent?: number | null // 0.1-100

```

- 所有字符串去首尾空白，空字符串视为 null（`config` 中除 `password` 外的字符串同理）。
- **修改是整体覆盖**：可空字段不传会被写成 null。
- 新建的支付方式**默认停用（`enable = 0`）**，需调用 toggle 启用；新建时随机生成 `uuid`。
- 前置条件：系统设置中必须配置了站点地址 `app_url`。

响应 `data`：`true`。

错误：

| 状态 | msg |
| --- | --- |
| 400 | 请在站点配置中配置站点地址 |
| 422 | 显示名称不能为空 |
| 422 | 网关参数不能为空 |
| 422 | 配置参数不能为空 |
| 422 | 自定义通知域名格式有误 |
| 422 | 百分比手续费范围须在0.1-100之间 |
| 400 | gate is not found |
| 404 | 支付方式不存在（修改时） |

#### POST `payments/:id/toggle` — 启用 / 停用

无 Body。响应 `data`：`true`。错误：404 `支付方式不存在`。

#### DELETE `payments/:id` — 删除

响应 `data`：`true`。错误：404 `支付方式不存在`。

#### POST `payments/sort` — 排序

Body：`{ ids: number[] }`（不能为空），按顺序设置 `sort = 1..n`。任一 ID 不存在返回 404 `支付方式不存在`；空数组返回 422。响应 `data`：`true`。

## 5. 礼品卡（`internal/usercenter`）

### 5.1 类型与字段含义

| type | 含义 | `value` 含义 | `plan_id` |
| --- | --- | --- | --- |
| 1 | 余额 | 充入余额，**分** | 不使用（保存时清空） |
| 2 | 时长 | 延长到期时间，**天** | 不使用 |
| 3 | 流量 | 增加流量，**GB** | 不使用 |
| 4 | 重置流量 | 不需要（可为 null） | 不使用 |
| 5 | 套餐 | 套餐有效期，**天**，**0 表示长期有效** | **必填**，必须存在 |

兑换时：时长、流量、重置流量类作用于用户选择的订阅（不选为主订阅）；套餐类不选订阅时新开订阅。

```ts
interface Giftcard {
  id: number
  code: string                   // 卡密
  name: string
  type: 1 | 2 | 3 | 4 | 5
  value: number | null           // 见上表
  plan_id: number | null
  limit_use: number | null       // 总可用次数，null 不限制
  used_user_ids: number[] | null // 已使用的用户 ID
  started_at: number             // Unix 秒，0 = 不限制
  ended_at: number               // Unix 秒，0 = 不限制
  created_at: number
  updated_at: number
}
```

### 5.2 接口

#### GET `giftcards` — 礼品卡列表

Query：`current`、`page_size`（10–100）、`sort`、`sort_type`。

- `sort` 白名单：`id`、`code`、`name`、`type`、`value`、`plan_id`、`limit_use`、`started_at`、`ended_at`、`created_at`、`updated_at`，其他值按 `id`。
- `sort_type=ASC` 升序，否则降序。

响应 `data`：`PageResult<Giftcard>`。

#### POST `giftcards` — 新建 / PUT `giftcards/:id` — 修改

Body：

```ts
interface GiftcardInput {
  name: string                   // 必填，最多 255 字符
  type: 1 | 2 | 3 | 4 | 5        // 必填
  value?: number | null          // type != 4 时必填且 >= 0
  plan_id?: number | null        // type = 5 时必填
  code?: string                  // 最多 255 字节；新建为空则随机 16 位；修改为空则保留原卡密
  limit_use?: number | null      // >= 0
  started_at?: number            // >= 0，0 不限制
  ended_at?: number              // >= 0，0 不限制；两者都 > 0 时 ended_at 不能早于 started_at
}
```

- 修改是整体覆盖（`used_user_ids` 不变）。
- 卡密不能与其他礼品卡重复。

响应 `data`：`true`。

错误：422 `Invalid parameters`；400 `Subscription plan does not exist`；409 `The gift card code already exists`；404 `The gift card does not exist`（修改时）。

#### POST `giftcards/batch` — 批量生成

Body：`GiftcardInput`（`code` 被忽略）+ `count: number`（1–500）。

成功直接返回 **CSV 文件 `giftcards.csv`**，列：`名称, 类型(金额/时长/流量/重置/套餐), 数值(金额为元；时长/套餐为“N天”；流量为“NGB”；重置为“-”), 开始时间, 结束时间(0 显示“不限制”), 可用次数, 礼品卡卡密, 生成时间`。

错误（JSON）：422 `The number of gift cards generated at a time is 1 to 500`；其他同新建。

#### DELETE `giftcards/:id` — 删除

响应 `data`：`true`。错误：404 `The gift card does not exist`。
