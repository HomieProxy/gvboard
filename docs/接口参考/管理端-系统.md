# 原生 API 接口参考：管理端（系统部分）

> 适用对象：管理端前端（Vue 3 + TypeScript + shadcn-vue）开发。
> 依据：`internal` 下各模块 handler / service / model 源码（以代码为准）。
> 覆盖模块：系统配置 `sysconfig`、统计与系统状态 `adminstat`、订阅风控与订阅模板 `subscribe`、插件 `plugin`、工单 `ticket`、公告与知识库 `content`、Telegram `telegram`、主题 `theme`。

---

## 0. 通用约定

### 0.1 路径前缀与认证

- 全部接口挂在 `{api}/{secure_path}` 下，`{api}` 为可配置的原生 API 前缀，`{secure_path}` 为设置项 `secure_path`（每次请求实时读取，修改后立即生效）。
- 本文所有路径都**相对于 `{api}/{secure_path}`**，例如 `GET /config` 实际为 `GET {api}/{secure_path}/config`。
- 认证：请求头 `Authorization`（与用户端相同的登录凭证）。
- **以下任一情况都返回统一 404 HTML 页面**（`Content-Type: text/html`，内容与 nginx 默认 404 页一致，**不是 JSON**）：
  - `secure_path` 不匹配或未设置；
  - 未登录、凭证失效；
  - 当前用户不是管理员；
  - 认证过程内部错误。
- 前端判断建议：HTTP 404 且响应 `Content-Type` 不是 `application/json` 时，视为“登录失效 / 无权限 / 管理端路径已变更”，跳转登录页；HTTP 404 且是 JSON 时为业务上的“记录不存在”。

### 0.2 统一响应格式（`internal/httpx/response.go`）

```ts
interface ApiBody<T> {
  code: number   // 0 成功；失败时与 HTTP 状态码一致：400/401/403/404/409/422/429/500
  msg: string    // 成功为 "ok"；失败为已按请求语言翻译的提示文案
  data?: T       // 成功时返回；失败时不返回该字段
}
```

| HTTP 状态 / code | 含义 |
|---|---|
| 200 / 0 | 成功 |
| 400 / 400 | 业务前置条件不满足（如插件需先停用、Telegram 请求失败） |
| 404 / 404（JSON） | 业务记录不存在（如“规则不存在”“插件不存在”“主题不存在”） |
| 422 / 422 | 参数校验失败（`msg` 为具体原因） |
| 500 / 500 | 服务器内部错误（`msg` 固定为“服务器内部错误”，细节只写日志） |

### 0.3 数据格式约定

- **时间**：全部为 Unix 时间戳（**秒**，整数），下文写作 `number /* 秒 */`。
- **金额**：统计接口中的金额单位为 **分**（整数），展示时除以 100。
- **流量**：`u`/`d` 为字节；排行接口中的 `total` 为 GB（小数）。
- **开关类字段**：数据库模型中的开关一般为 `0 | 1` 整数；部分请求体使用 `boolean`，下文逐一标注。
- 后台接口的 `msg` 多为中文直出；工单模块的错误为英文翻译键，经翻译后返回。

### 0.4 分页方式（注意两种结构不同）

| 接口 | 请求参数 | 每页条数 | 响应结构 |
|---|---|---|---|
| `GET /stat/user`、`GET /system/logs`、`GET /subscribe-guard/logs` | `current`（从 1 开始，<1 视为 1）、`page_size` | 限制在 10～100（<10 按 10，>100 按 100） | `{ data: T[], total: number }` |
| `GET /tickets` | `current`、`page_size` | 同上 10～100 | `{ total: number, list: T[] }` |
| 其余列表 | 无分页，一次返回全部 | — | `T[]` |

```ts
interface DataPage<T> { data: T[]; total: number }  // stat/user、system/logs、subscribe-guard/logs
interface ListPage<T> { total: number; list: T[] }  // tickets
```

## 1. 系统配置 `internal/sysconfig`

### 1.1 接口列表

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/config` | 读取配置（可按分组） |
| PUT | `/config` | 保存配置（只修改提交的键） |
| GET | `/config/email-templates` | 可选的邮件模板名列表 |
| POST | `/config/test-mail` | 向当前管理员邮箱发送测试邮件 |
| GET | `/config/mail-templates` | 邮件模板列表及各类邮件是否已自定义 |
| GET | `/config/mail-templates/:theme/:name` | 读取某个模板中一类邮件的内容 |
| PUT | `/config/mail-templates/:theme/:name` | 保存一类邮件的内容；内置模板提交空内容恢复默认 |
| POST | `/config/mail-templates` | 新增模板（复制已有模板） |
| DELETE | `/config/mail-templates/:theme` | 删除新增的模板 |
| POST | `/config/mail-templates/preview` | 用示例数据预览（不保存、不发送） |

#### GET `/config`

- 查询参数：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| group | string | 否 | 分组名：`site`/`safe`/`subscribe`/`invite`/`deposit`/`ticket`/`frontend`/`server`/`email`/`telegram`/`app`/`gvboard`。为空返回全部分组；分组不存在返回 422“配置分组不存在”。`legacy`、`internal`（如自定义邮件模板）分组永远不返回 |

- 响应 `data`：

```ts
// 外层键为分组名，内层键为设置键名；值为当前值（未设置时为默认值）
type ConfigData = Record<string, Record<string, ConfigValue>>
type ConfigValue = string | number | string[] | null
```

- 值的 JSON 类型（与设置项类型对应）：
  - 字符串 → `string`
  - 整数 → `number`（整数）
  - 小数 → `number`；`commission_distribution_l1/l2/l3` 默认 `null`
  - 开关 → `number`，只会是 `0` 或 `1`
  - 字符串数组 → `string[]`
- **敏感项（密码、密钥）明文返回**，内置管理端直接明文显示，便于核对已填写的内容。

#### PUT `/config`

- 请求体：JSON 对象 `{ "键名": 值, ... }`，只修改提交的键；最大 4 MB（订阅模板较大）。
- 规则：
  - 任一键未知（或属于 `legacy`、`internal`）→ 422“未知配置项：xxx”；任一项校验失败 → **整体不保存**，422，`msg` 形如“设置项 xxx: 原因”。
  - 空对象 → 422“没有需要保存的配置”；JSON 解析失败 → 422“参数有误”。
- 值的宽松转换（`setting.Coerce`）：
  - 字符串项：接受字符串 / 数字 / 布尔（布尔转 `"1"`/`"0"`）。
  - 整数项：接受整数、整数值的小数、数字字符串、布尔；**空字符串视为“未设置”，保存后读取回落到默认值**。
  - 小数项：接受数字或数字字符串；空字符串同上视为未设置。
  - 开关项：接受 `true/false`、`0/1`、`"0"/"1"`、`"true"/"false"`、`"on"/"off"`、`"yes"/"no"`、空串（视为 0）；非 0 数字视为 1。
  - 字符串数组项：接受数组，或**逗号分隔的字符串**（会去空格、去空项）。
  - `null`：视为未设置（读取回落默认值）。
- 响应 `data`：`true`。
- 注意：修改 `secure_path` 后管理端路径立即变化，前端需用新路径重新拼接 `{api}/{secure_path}`，否则后续请求全部 404。

#### GET `/config/email-templates`

- 响应 `data`：`string[]`，内置与新增的邮件模板名（按字母排序，如 `classic`、`default`）。`email_template` 只能取其中之一。

#### POST `/config/test-mail`

- 请求体：无。收件人为当前登录管理员的邮箱，标题/内容按请求语言生成。
- 同步发送并写入邮件日志，**发送失败也返回 code 0**，需看 `data.error` 判断：

```ts
interface MailLog {
  id: number
  email: string
  subject: string
  template_name: string
  error: string | null   // null 表示发送成功；否则为失败原因
  created_at: number     // 秒
  updated_at: number     // 秒
}
```

#### 邮件模板管理 `/config/mail-templates`

一个“模板”（theme）包含 5 类邮件（name）：`verify` 邮箱验证码、`notify` 通知（公告、群发邮件、工单回复、测试邮件）、`remindExpire` 到期提醒、`remindTraffic` 流量提醒、`mailLogin` 邮件链接登录。内置模板 `default`、`classic` 可直接修改（覆盖内容单独保存，可随时恢复默认），不能删除；也可复制已有模板新增，新增的模板可修改、删除。自定义内容统一保存在设置项 `email_templates_custom` 中，该项不在 `GET /config` 中返回，也不能通过 `PUT /config` 修改。

模板使用 Go `html/template` 语法：变量写作 `{{.name}}`，值会按所在位置自动转义；`{{nl2br .content}}` 把换行转为 `<br />`。各类邮件可用变量：

| name | 变量 |
|---|---|
| verify | `name` 站点名称、`url` 站点地址、`code` 验证码 |
| notify | `name`、`url`、`content` 通知内容（管理员群发内容按 HTML 原样输出，其余内容转义） |
| remindExpire / remindTraffic | `name`、`url`、`subscription` 订阅名称 |
| mailLogin | `name`、`url`、`link` 登录链接 |

- `GET /config/mail-templates` 响应：

```ts
interface MailTheme {
  theme: string        // 模板名
  builtin: boolean     // 是否内置
  active: boolean      // 是否为当前使用的模板（email_template）
  templates: { name: string; title: string; vars: string[]; custom: boolean }[]  // custom：内置模板中该类邮件是否已修改
}
type Data = MailTheme[]
```

- `GET /config/mail-templates/:theme/:name` 响应 `{ content: string; default: string; custom: boolean }`：`content` 为当前生效内容，`default` 为内置内容（新增模板为空字符串）。
- `PUT /config/mail-templates/:theme/:name` 请求体 `{ "content": "..." }`：
  - 内置模板提交空字符串或与内置内容相同 → 删除覆盖内容，恢复默认。
  - 新增模板内容不能为空。
  - 单类邮件最大 64 KB；保存前用示例数据试渲染，语法错误、调用不存在的函数等 → 422 并给出原因；全部自定义内容合计不超过 2 MB。
- `POST /config/mail-templates` 请求体 `{ "theme": "新模板名", "from": "复制自" }`：名称只能包含字母、数字、下划线、短横线（≤ 32 位），不能与已有模板重名；新增模板最多 20 个。
- `DELETE /config/mail-templates/:theme`：内置模板与正在使用的模板不能删除（422）。
- `POST /config/mail-templates/preview` 请求体 `{ "name": "verify", "content": "..." }`，响应 `{ html: string }`：用站点名称、站点地址与示例验证码 / 订阅名 / 链接渲染，不保存、不发送。前端应在 `sandbox` iframe 中显示。

### 1.2 全部设置项（`internal/setting/keys.go`）

列说明：
- **类型**：字符串 / 整数 / 小数 / 开关（0 或 1）/ 字符串数组。
- **敏感**：`是` 表示密码、密钥类，建议用密码框（接口仍明文返回）。
- **含义**：来源于原管理端（`v2board/public/assets/admin/umi.js`）中文说明、`ConfigSave.php` 及 Gvboard 代码注释；无出处的标注“推断”。
- **定义级校验**：写在 `keys.go` 的 `Validate`，读取与保存时都生效；管理端保存时额外校验见 1.3。

### 3.1 规则字段与匹配逻辑

```ts
type RuleTarget = 'ua' | 'header' | 'ip' | 'flag' | 'client'
type RuleMatch  = 'contains' | 'equals' | 'prefix' | 'regex' | 'empty' | 'cidr'
type RuleAction = 'allow' | 'log' | 'empty' | 'deny'

// 响应中的规则（v2_subscribe_rule）
interface SubscribeRule {
  id: number
  name: string
  target: RuleTarget
  header: string            // 仅 target = header 时有值，否则 ""
  match_type: RuleMatch
  pattern: string | null    // 多个值按行（\n）分隔；empty 匹配时为 null
  negate: 0 | 1             // 1 取反：不匹配时视为命中
  action: RuleAction
  priority: number          // 越小越先匹配
  enabled: 0 | 1
  hit_count: number         // 命中次数（修改规则不重置）
  last_hit_at: number | null// 最后命中时间，秒
  created_at: number
  updated_at: number
}

// 新建 / 修改的请求体（注意 negate、enabled 在请求中是 boolean）
interface RuleInput {
  name: string        // ≤ 64 字符，会去首尾空格
  target: RuleTarget
  header?: string     // target = header 时必填，须匹配 ^[A-Za-z0-9-]{1,64}$
  match_type: RuleMatch
  pattern?: string    // 见下表
  negate?: boolean
  action: RuleAction
  priority?: number   // -1000000 ～ 1000000，默认 0
  enabled?: boolean   // 默认 false（未传即停用）
}
```

| 字段 | 取值与含义 |
|---|---|
| target | `ua` User-Agent；`header` 指定请求头；`ip` 客户端 IP；`flag` 订阅 URL 中 `flag` 参数原值（未传为空）；`client` 系统识别出的客户端格式名（见 `/subscribe-guard/clients`） |
| match_type | `contains` 包含；`equals` 等于；`prefix` 前缀（这三种不区分大小写，pattern 每行一个值，1～200 行，任一匹配即命中）；`regex` 正则（不区分大小写，只填一个表达式，≤1000 字符，Go RE2 语法）；`empty` 值为空（pattern 忽略）；`cidr` IP 或 CIDR（每行一个，1～200 行）。**`ip` 只能用 `cidr`，`cidr` 只能用于 `ip`** |
| pattern | 总长 ≤ 10000 字节；保存时去掉空行与首尾空格 |
| action | `allow` 放行：跳过后续规则、频率限制与防分享；`log` 只记录命中，继续匹配后续规则；`empty` 返回 200 空内容；`deny` 返回统一 404 |
| 匹配顺序 | 仅启用的规则，按 `priority ASC, id ASC`；命中 `log` 继续，命中其它动作即结束 |

校验失败均返回 422，`msg` 为中文原因（如“IP 只能按 IP / CIDR 匹配”“正则表达式不正确”）。

### 4.1 数据结构

```ts
interface PluginField {          // 配置项定义（Go 插件 Fields() / JS 插件 plugin.json 的 config）
  key: string                    // ^[a-zA-Z][a-zA-Z0-9_]{0,63}$
  label: string
  type: 'string' | 'text' | 'password' | 'number' | 'bool' | 'select'
  default: any                   // 可能为 null
  options?: { value: string; label: string }[]  // type = select 时
  required: boolean
  help?: string
}
// 类型与表单控件：string 单行（≤2000 字符）；text 多行（≤65535）；password 密码框（≤2000）；
// number 数值（值为 number）；bool 开关（值为 boolean）；select 单选（值必须为 options 中的 value，可为 ""）

interface PluginRoute { method: string; path: string; scope: 'public' | 'admin' }

interface PluginFeatures {
  events: string[]     // 订阅的事件名（排序）
  filters: string[]    // 注册的过滤器名（排序）
  routes: PluginRoute[]
  jobs: string[]       // 定时任务，格式 "名称 (cron 表达式)"
  payments: string[]   // 注册的支付方式
  formats: string[]    // 注册的订阅格式名
}

interface PluginPermission { key: string; description: string }

interface PluginPackage {        // JS 插件安装包信息
  sha256: string
  size: number                   // 字节
  http: string[]                 // 允许访问的域名，如 "api.example.com"、"*.example.com"、"api.example.com:8443"
  permissions: PluginPermission[]
}

interface PluginView {
  code: string
  name: string
  version: string
  author: string
  description: string
  url: string
  type: 'go' | 'js'
  status: 'ok' | 'error' | 'missing'  // ok 正常；error 加载失败（不能启用）；missing 数据库有记录但程序中已没有
  error?: string                      // status = error 时的原因
  enabled: boolean                    // status = error 时恒为 false
  installed_at: number                // 安装时间，秒；无数据库记录时为 0
  fields: PluginField[]
  config: Record<string, any>         // 当前配置（含默认值）；password 类型同样明文返回
  features: PluginFeatures
  package?: PluginPackage             // 仅 JS 插件
}
```

### 4.2 接口说明

#### GET `/plugins`

响应 `PluginView[]`：程序中的插件按 `code` 排序，其后是 `missing` 状态的插件。

#### GET `/plugins/:code`

响应 `PluginView`。不存在 404（JSON）“插件不存在”。

#### POST `/plugins/:code/enable`

- 无请求体，响应 `true`（已启用也返回 `true`）。
- 失败：插件不存在 404；`missing` 状态 400“程序中已没有该插件”；加载失败 400“插件加载失败，不能启用：…”；必填配置为空 422“请先完成插件配置：xxx 不能为空”；插件启用回调失败或超时（30 秒）400“插件启用失败：…”。

#### POST `/plugins/:code/disable`

无请求体，响应 `true`（已停用也返回 `true`）。无记录 404。

#### PUT `/plugins/:code/config`

- 请求体：`{ "config": { "键": 值, ... } }`，`config` 必须是对象（缺失 422“参数有误”）。
- 未提交的键保持原值；提交了未声明的键 422“未知配置项 xxx”；类型不符或超长 422；保存后必填项为空 422。
- 值转换：文本类接受字符串 / 数字；number 接受数字或数字字符串；bool 接受 `true/false`、`0/1`、`"0"/"1"`、`"true"/"false"`、`""`。
- 立即生效，响应 `true`。`missing` 插件不能保存（404）。

#### DELETE `/plugins/:code`

- 只能删除 **JS 插件** 或 **`missing` 状态的插件**；程序内置的 Go 插件 400“只能删除已从程序中移除的插件”。
- 启用中 400“请先停用插件”。删除时一并删除其安装包与 KV 数据。响应 `true`。

#### POST `/plugins/upload`（JS 插件安装，两步确认）

- 请求：`multipart/form-data`
  - `file`：zip 安装包，**≤ 2 MB**（解压后总计 ≤ 8 MB、文件数 ≤ 200、单文件 ≤ 2 MB），必填；
  - `sha256`：可选。**不带时只预览，带上预览返回的 `sha256` 时才安装 / 更新**。
- 第一步（预览）响应 `PluginPackageView`：

```ts
interface PluginPackageView {
  code: string; name: string; version: string; author: string; description: string; url: string
  sha256: string
  size: number
  http: string[]                    // 插件可访问的外部域名（已规范化、去重）
  permissions: PluginPermission[]   // 插件申请的权限及中文说明（已排序去重）
  fields: PluginField[]
  installed_version: string         // 已安装版本；"" 表示新安装
}
```

- **需要管理员确认的内容就是 `http`（可访问的域名）与 `permissions`（权限）**。前端应在确认弹窗中逐条展示，管理员确认后用同一个文件 + `sha256` 再次提交。
  - 域名规则：只能填域名（不能是 IP），`*.` 开头表示任意子域名；不带端口只允许 80/443，带端口则只允许该端口；最多 20 个。
  - 全部权限：

| key | 说明 |
|---|---|
| user.read | 读取用户基本信息（邮箱、余额、佣金、封禁状态等，不含密码） |
| user.balance | 增加或扣除用户余额 |
| subscription.read | 读取用户的订阅（套餐、流量、到期时间，不含订阅令牌与 UUID） |
| subscription.write | 给订阅增加流量、延长到期时间 |
| order.read | 读取用户的订单 |

- 第二步（安装）响应：安装后的 `PluginView`。新安装默认**停用**；更新时保留启用状态与配置并立即生效。
- 失败：缺少文件或超限 422“请上传不超过 2 MB 的 zip 安装包”；包内容错误 422（`msg` 为具体原因，如“安装包中缺少 plugin.json”“未知权限 …”）；`sha256` 与本次文件不一致 400“安装包与预览时不一致，请重新上传并确认”；标识与 Go 插件冲突 400“插件标识与程序内置插件冲突”。
- `plugin.json` 结构（供说明用）：`code`（小写字母开头，2～32 位，小写字母 / 数字 / `_` / `-`）、`name`（必填，≤64）、`version`、`author`、`description`、`url`、`main`（默认 `main.js`）、`http`、`permissions`、`config`（`PluginField[]`，≤100 项），不允许未知字段。

```ts
  show?: boolean     // 不传：新建为 0（隐藏），修改保持原值
}
```

- `GET /knowledge`：响应 `AdminArticleBrief[]`，按 `sort` 升序（`sort` 为 null 的排最前），再按 `id`。
- `GET /knowledge/categories`：响应 `string[]`，按首次出现顺序去重。
- `GET /knowledge/:id`：响应 `Knowledge`。
- `POST /knowledge` / `PUT /knowledge/:id`：请求体 `ArticleInput`，响应保存后的 `Knowledge`。
- `POST /knowledge/:id/show`：`{ "show": boolean }`，响应 `true`。
- `POST /knowledge/sort`：请求体 `{ "ids": number[] }`，按数组顺序把 `sort` 设为 1、2、3…（不更新 `updated_at`）。数组不能为空、不能重复、必须全部存在（否则 422 / 404）。只更新传入的文章。响应 `true`。
- `DELETE /knowledge/:id`：响应 `true`。

## 7. Telegram（管理端）`internal/telegram/handler.go`

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/telegram/apply` | 按当前设置初始化机器人 |
| GET | `/telegram/info` | Webhook 状态 |

> 使用流程：先 `PUT /config` 保存 Telegram 分组设置，再调用 `POST /telegram/apply` 生效。

#### POST `/telegram/apply`

- 无请求体。动作：校验 Token（getMe）、设置命令菜单（默认 + zh + en），然后：
  - `telegram_mode = webhook`：`telegram_webhook_secret` 为空时自动生成并保存，设置 Webhook 为 `当前请求的协议与主机 + {api} + /telegram/webhook/{secret}`；
  - `telegram_mode = polling`：删除 Webhook（由服务端长轮询）。
- 响应：

```ts
interface TelegramApplyResult {
  mode: 'webhook' | 'polling'
  username: string        // 机器人用户名
  webhook_url?: string    // 仅 webhook 模式
}
```

- 失败：Token 未设置 400“Telegram bot is not enabled”（已翻译）；调用 Bot API 失败 400“Telegram request failed: 原因”。
- 注意：Webhook 地址取自**本次请求的 Host**（及 `X-Forwarded-Proto`），前后端分离部署时应确保请求到达的 API 域名对 Telegram 可公网访问。

#### GET `/telegram/info`

```ts
interface TelegramWebhookInfo {
  url: string                    // 当前 Webhook 地址，长轮询模式为 ""
  pending_update_count: number
  last_error_date?: number       // 秒
  last_error_message?: string
  max_connections?: number
  has_custom_certificate: boolean
}
```

失败情况同 apply。

## 8. 主题 `internal/theme/handler.go`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/themes` | 主题列表与当前主题 |
| PUT | `/themes/active` | 切换主题 |
| GET | `/themes/:id/config` | 主题配置 |
| PUT | `/themes/:id/config` | 保存主题配置 |

> 主题仅在前后端不分离部署时用于用户端渲染。外部主题目录每次访问时读取，放入后无需重启；外部目录同名主题优先于内置主题。

```ts
interface ThemeField {
  label: string
  placeholder?: string
  field_name: string                       // ^[A-Za-z0-9_]{1,64}$
  field_type: 'input' | 'select' | 'textarea'
  select_options?: Record<string, string>  // 值 → 显示名，保留原顺序（JSON 对象）
  default_value?: any
}
interface ThemeView {
  id: string            // 目录名，即 frontend_theme 取值
  name: string
  description: string
  version: string
  images: string        // 预览图地址
  configs: ThemeField[]
  builtin: boolean      // 是否内置主题
}
interface ThemesResponse { themes: ThemeView[]; active: string }
```

#### GET `/themes`

响应 `ThemesResponse`。列表按 `id` 排序，定义有误的主题不出现。`active` 为当前设置值（不校验是否存在；不存在时用户端实际回落到 `default`）。

#### PUT `/themes/active`

- 请求体：`{ "id": string }`。
- 主题不存在 404（JSON）“主题不存在”；主题定义有误 422（原因）。响应 `true`。

#### GET `/themes/:id/config`

响应 `Record<string, string | number | boolean>`：只含主题定义的配置项，未保存的项取 `default_value`，无默认值为 `""`。

#### PUT `/themes/:id/config`

- 请求体：扁平对象 `{ "field_name": 值, ... }`，≤ 1 MB。
- 规则：只保留定义中的配置项；**未提交的项保存为 `""`**（需整表提交）；值只能是字符串、数字或布尔；字符串 ≤ 64 KB；`select` 的值必须是 `select_options` 的键（空串除外）。
- 响应：保存后的配置 `Record<string, any>`。
