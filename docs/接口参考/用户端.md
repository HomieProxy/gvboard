# Gvboard 原生 API 参考：用户端与访客

> 本文以 `internal` 下的代码为准整理（handler + service + model），供用户端前端（Vue 3 + TypeScript）对接。
> 下文所有路径都**相对于原生 API 前缀 `{api}`**（配置项 `api.prefix`，例如 `/api/k3f9x2`）。
> 管理端接口（`{api}/{secure_path}/...`）、节点接口（`/api/v1/server`、`/api/v2/server`）、`/api/v1` 兼容层不在本文范围内。

---

## 0. 通用约定

### 0.1 获取 API 前缀与站点配置

| 部署方式 | 获取方式 |
|---|---|
| 不分离部署（`server.mode = all`） | 页面中注入 `window.APP_CONFIG`，前端直接读取，**不需要**请求 `GET /site`（该接口在此模式下不存在，会返回 404） |
| 分离部署（`server.mode = api`） | 前端自行配置 `{api}`，然后请求 `GET {api}/site` 获取站点配置 |

不分离部署时 `window.APP_CONFIG` 的结构：

```ts
interface AppConfig {
  api: string                 // 原生 API 前缀，例如 "/api/k3f9x2"
  site: SiteInfo              // 同 GET /site 的 data.site
  register: RegisterInfo      // 同 GET /site 的 data.register
  theme: { id: string; config: Record<string, unknown> }  // 当前主题与主题配置
}
```

健康检查：`GET {api}/ping` 返回 `{"code":0,"msg":"ok","data":"pong"}`（无需登录）。

### 0.2 统一响应格式（`internal/httpx/response.go`）

```ts
interface ApiBody<T = unknown> {
  code: number   // 0 表示成功；失败时与 HTTP 状态码相同（400/401/403/404/409/422/429/500）
  msg: string    // 成功时固定为 "ok"；失败时为按请求语言翻译后的错误信息，可直接展示给用户
  data?: T       // 仅成功时存在；值为 null/nil 时字段会被省略（Go 的 omitempty）
}
```

- **成功**：HTTP 200，`code = 0`，`msg = "ok"`，`data` 为业务数据。很多“操作类”接口的 `data` 是 `true`。
- **失败**：HTTP 状态码 = `code`，**响应中没有 `data` 字段**。

| HTTP 状态 / code | 含义 | 典型场景 |
|---|---|---|
| 400 | 业务错误（BadRequest） | 密码错误、余额不足、优惠券无效等 |
| 401 | 未登录或登录失效 | 认证中间件：缺少 / 无效 token、会话已删除 |
| 403 | 禁止 | 账户被封禁、注册关闭、订阅数量达上限、不允许更换套餐 |
| 404 | 记录不存在（JSON） | 订阅 / 订单 / 工单不存在（注意与下面的“统一 404 页面”区分） |
| 409 | 冲突 | 邮箱已存在、存在未支付订单 |
| 422 | 参数校验失败 | 请求体不是合法 JSON / 字段类型不对 / 必填缺失 / 格式不对 |
| 429 | 频率限制 | 注册过于频繁、密码错误次数过多、验证码发送过于频繁 |
| 500 | 服务器内部错误 | `msg` 为“服务器内部错误”；支付网关发起失败时 `msg` 是网关返回的说明 |

**参数校验失败**：JSON 解析失败或字段类型不匹配时统一返回 HTTP 422 `{"code":422,"msg":"参数有误"}`（原文 `Invalid parameters`；工单、内容模块原文为 `Invalid parameter`）；业务字段校验（如“邮箱不能为空”）同样是 422，`msg` 为具体原因。**没有逐字段的错误对象**，前端直接展示 `msg` 即可。

**统一 404 页面（非 JSON）**：任何**不存在的路由**、方法不匹配、`GET /site` 在不分离模式下、订阅 / App 接口 token 无效、插件未启用等场景，返回的是 **HTTP 404 + `Content-Type: text/html` 的 nginx 风格页面**，不是 JSON。前端的响应拦截器必须能处理非 JSON 的 404（按 Content-Type 判断）。

> 注意：同为 404，业务“记录不存在”是 JSON（`code: 404`），路由不存在是 HTML。

### 0.3 认证（`internal/auth`）

- 登录 / 注册 / 验证码登录成功后返回 `data.token`（HS256 JWT）。
- 之后每个需登录的请求携带请求头：

  ```
  Authorization: Bearer <token>
  ```

  服务端也接受不带 `Bearer ` 前缀的裸 token，但建议统一带前缀。
- **token 没有过期时间**（JWT 不含 `exp`）。它在服务端 Redis 中对应一条“会话”，以下情况会话被删除，token 立即失效：
  - 用户修改密码（`POST /user/password`）——**包括当前会话**，前端需跳转登录页；
  - 通过邮箱验证码重置密码；
  - 用户在“活动会话”中删除该会话；
  - 管理员封禁 / 踢下线等。
- 认证失败响应：

  | 情况 | HTTP | 响应体 |
  |---|---|---|
  | 缺少 token、token 无效、会话已删除、用户不存在 | 401 | `{"code":401,"msg":"未登录或登录已过期"}`（按语言翻译，原文 `Not logged in or login expired`） |
  | 账户已被封禁（已登录会话同样失效） | 403 | `{"code":403,"msg":"该账户已被停止使用"}`（原文 `Your account has been suspended`） |

  建议：拦截器遇到 **401** 清除 token 并跳转登录；遇到 **403 且 msg 为封禁文案** 也应清除 token（403 还会用于其它业务错误，不能一律跳登录）。
- 每次请求都会实时读取用户的 `is_admin` / `banned`，后台修改即时生效。

### 0.4 多语言（`internal/i18n`）

- 请求头：**`Content-Language`**（与原项目一致，不是 `Accept-Language`）。
- 支持的语言代码：**`zh-CN`**、**`en-US`**（不区分大小写，例如 `zh-cn` 也可）。
- 不传或传了不支持的值时，使用服务端配置的默认语言 `app.locale`（默认 `zh-CN`）。
- 影响范围：所有错误 `msg` 的翻译、发送邮箱验证码的邮件标题、佣金提现工单的标题与内容、知识库“需有效订阅才能查看”提示文案。
- 分离部署跨域时，CORS 已放行 `Authorization, Content-Type, Content-Language, X-Requested-With` 四个请求头。

### 0.5 跨域（分离部署）

- 只有配置项 `cors.allow_origins` 白名单中的 Origin 才会得到 CORS 头，且仅对 `{api}` 前缀生效；`Access-Control-Allow-Credentials: true`。
- 预检允许的请求头**只有**上面 4 个，**不包含 `If-None-Match`**；服务端**没有**设置 `Access-Control-Expose-Headers`，跨域时 JS 读不到 `ETag` 响应头（见 9.1 节）。

### 0.6 数据单位约定（全局）

| 类别 | 单位 | 说明 |
|---|---|---|
| 金额 | **分**（整数） | 余额、佣金、订单金额、套餐价格、优惠金额、手续费、礼品卡余额值等。展示时 ÷100。例外见各接口说明（如 `pending_commission` 可能带小数） |
| 流量 | **字节** | 订阅 `transfer_enable` / `u` / `d`、流量明细 `u` / `d` |
| 套餐流量 | **GB** | 仅 `Plan.transfer_enable` 是 GB（1 GB = 1073741824 字节） |
| 时间 | **Unix 秒**（整数） | 所有 `*_at` 字段。`expired_at = null` 表示长期有效 |
| 比例 | 百分比整数 | `discount`、`commission_rate`、优惠券按比例时的 `value`（如 20 表示 20%） |
| 布尔 | 见各字段 | 本项目新接口多用 `boolean`；直接透传数据库模型的字段（如 `Plan.show`、`Notice.show`）是 `0/1` 整数 |

### 0.7 请求体格式

- 除 `passport` 模块外，所有 POST/PUT 都只解析 **JSON**（`Content-Type: application/json`）。
- `passport` 模块（注册、登录等）用 Gin 的 `ShouldBind`，**JSON 与表单都可以**，建议统一 JSON。
- 请求体为空时视为所有字段未传（不会报 422）。
- 请求体大小上限默认 8 MB（`server.max_body_bytes`）。

### 0.8 分页约定

本项目用户端只有两处分页，**返回格式不一致**，请注意：

| 接口 | 参数 | 返回 |
|---|---|---|
| `GET /user/notices` | `current`（页码，从 1 开始，默认 1）、`page_size`（默认 5，范围 1–100） | `{ total: number; list: Notice[] }` |
| `GET /user/invite/commissions` | `current`（默认 1）、`page_size`（小于 10 时按 10，最大 100） | `{ total: number; data: CommissionDetail[] }`（**键名是 `data` 不是 `list`**） |

其它列表接口（订单、工单、订阅、套餐等）都**不分页**，一次返回全部。

### 0.9 通用 TypeScript 类型

```ts
type UnixSeconds = number
type Cents = number          // 金额：分
type Bytes = number          // 流量：字节

interface Page<T> { total: number; list: T[] }
```

## 1. 认证与访客（`internal/passport`）

| 方法 | 路径 | 登录 | 说明 |
|---|---|---|---|
| POST | `/auth/register` | 否 | 注册 |
| POST | `/auth/login` | 否 | 密码登录 |
| POST | `/auth/reset-password` | 否 | 邮箱验证码重置密码 |
| POST | `/auth/email-code` | 否 | 发送邮箱验证码 |
| POST | `/auth/code-login` | 否 | 快捷登录码登录 |
| POST | `/auth/quick-login` | **是** | 生成快捷登录链接 |
| POST | `/invite/visit` | 否 | 邀请链接访问计数 |
| GET | `/site` | 否 | 公开站点配置（**仅分离部署**） |

```ts
interface AuthResult {
  token: string       // 放入 Authorization: Bearer <token>
  is_admin: boolean   // 是否管理员（管理端入口是否显示由前端决定）
}
```

### 1.1 POST `/auth/register` 注册

请求体：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `email` | string | 是 | 最长 64，仅可见 ASCII 字符，严格邮箱格式 |
| `password` | string | 是 | 至少 8 个字符 |
| `invite_code` | string | 视设置 | `register.invite_required = true` 时必填 |
| `email_code` | string | 视设置 | `register.email_code = true` 时必填，6 位数字 |
| `captcha` | string | 视设置 | `register.captcha_key` 非空时必填（reCAPTCHA 的 response） |

响应 `data: AuthResult`（注册即登录）。

检查顺序与错误：

| 条件 | HTTP | 文案原文 |
|---|---|---|
| 邮箱为空 / 格式错误 | 422 | `Email can not be empty` / `Email format is incorrect` |
| 密码为空 / 少于 8 位 | 422 | `Password can not be empty` / `Password must be greater than 8 digits` |
| 同 IP 注册过于频繁（开启 IP 限制时） | 429 | `Register frequently, please try again after :minute minute` |
| 人机验证失败 | 400 | `Invalid code is incorrect` |
| 邮箱后缀不在白名单 | 400 | `Email suffix is not in the Whitelist` |
| 开启 Gmail 别名限制且邮箱前缀含 `.` 或 `+` | 400 | `Gmail alias is not supported` |
| 注册已关闭 | 403 | `Registration has closed` |
| 强制邀请但未填邀请码 | 400 | `You must use the invitation code to register` |
| 邮箱验证码错误 | 400 | `Incorrect email verification code` |
| 密码计算排队超过 3 秒（同时登录 / 注册的请求过多） | 429 | `System busy, please try again later.` |
| 邮箱已存在 | 409 | `Email already exists` |
| 强制邀请且邀请码无效 | 400 | `Invalid invitation code` |

> 未开启强制邀请时，填了无效邀请码不会报错，只是不记录邀请人。
> 若设置了试用套餐（`try_out_plan_id`），注册后会自动给主订阅开通试用。

### 1.2 POST `/auth/login` 密码登录

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `email` | string | 是 | 邮箱 |
| `password` | string | 是 | 至少 8 位 |

响应 `data: AuthResult`。

错误：邮箱 / 密码格式 422；开启 IP 登录限制且同一 IP 次数超限时 `Too many requests, please try again later.`（429）；`There are too many password errors, please try again after :minute minutes.`（429）；`Incorrect email or password`（400，用户不存在也返回此文案）；密码计算排队超过 3 秒时 `System busy, please try again later.`（429）；`Your account has been suspended`（403）。

### 1.3 POST `/auth/reset-password` 重置密码

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `email` | string | 是 | 严格邮箱格式 |
| `email_code` | string | 是 | 6 位数字（先调用 `/auth/email-code`，`scene = "reset"`） |
| `password` | string | 是 | 新密码，8–64 个字符 |

响应 `data: true`。成功后该用户**全部会话失效**。

错误：`Email verification code cannot be empty`（422）；`Incorrect email verification code`（400）；验证码错误累计 3 次后 5 分钟内拒绝：`Reset failed, Please try again later`（429）；`This email is not registered in the system`（400）。

### 1.4 POST `/auth/email-code` 发送邮箱验证码

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `email` | string | 是 | 严格邮箱格式 |
| `scene` | string | 否 | `"register"`：要求邮箱**未注册**；`"reset"`：要求邮箱**已注册**；不传或空串：不检查。其它值返回 422 |
| `captcha` | string | 视设置 | 开启人机验证时必填 |

响应 `data: true`。验证码 6 位数字，**有效期 300 秒**。

限制与错误：
- 同一 IP 每分钟最多 3 次：`Too many requests, please try again later.`（429）
- 同一邮箱 60 秒内只能发一次：`Email verification code has been sent, please request again later`（429）——前端倒计时 60 秒即可
- `This email is registered`（409，scene=register）；`This email is not registered in the system`（400，scene=reset）
- 白名单 / Gmail 别名 / 人机验证错误同注册

### 1.5 POST `/auth/code-login` 快捷登录码登录

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | string | 是 | 快捷登录链接中的 `verify` 参数（一次性，60 秒有效） |

响应 `data: AuthResult`。错误：`Token error`（400，码无效/已用/过期）；`The user does not exist`（400）；`Your account has been suspended`（403）。

### 1.6 POST `/auth/quick-login` 生成快捷登录链接（需登录）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `redirect` | string | 否 | 登录后跳转的前端页面，默认 `"dashboard"` |

响应 `data: string`，格式固定：

```
{站点地址}/#/login?verify={code}&redirect={redirect}
```

站点地址取设置 `app_url`，未设置时用当前请求的协议 + Host。**用户端前端的 `/#/login` 路由必须处理 `verify` 参数**：读到后调用 `POST /auth/code-login`，成功后跳转 `redirect`。链接 60 秒内有效、只能用一次。

### 1.7 POST `/invite/visit` 邀请链接访问计数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | string | 否 | 邀请码；为空或不存在时静默忽略 |

响应 `data: true`。用于注册页带邀请码打开时统计 PV。

### 1.8 GET `/site` 公开站点配置（仅分离部署）

```ts
interface SiteConfig {
  site: SiteInfo
  register: RegisterInfo
}
interface SiteInfo {
  name: string          // 站点名称
  description: string   // 站点描述
  url: string           // 站点地址（app_url），可能为空
  logo: string          // Logo URL，可能为空
  terms_url: string     // 服务条款链接，可能为空
  home: boolean         // 访客访问根路径时是否显示首页（设置项 home_enable）；为 false 时直接进入登录页
}
interface RegisterInfo {
  closed: boolean            // 是否关闭注册
  email_code: boolean        // 注册是否需要邮箱验证码
  invite_required: boolean   // 是否强制邀请码
  email_suffixes: string[]   // 邮箱后缀白名单，空数组表示不限制
  captcha_key: string        // reCAPTCHA site key，空串表示未开启人机验证
}
```

### 2.1 GET `/user/info`

```ts
interface UserInfo {
  id: number
  email: string
  balance: Cents                  // 账户余额（分）
  commission_balance: Cents       // 可用佣金（分）
  discount: number | null         // 会员折扣百分比，例如 10 表示下单优惠 10%；null 无折扣
  commission_rate: number | null  // 个人佣金比例（%），null 表示使用系统默认
  telegram_bound: boolean         // 是否已绑定 Telegram
  subscription_limit: number      // 可拥有的订阅数量上限（个人设置优先，否则系统设置）
  avatar_url: string              // Cravatar 头像地址
  last_login_at: UnixSeconds | null
  created_at: UnixSeconds
}
```

> 订阅相关信息（流量、到期时间、订阅链接）不在这里，见 `/user/subscriptions`。

### 2.2 GET `/user/stat`

```ts
interface UserStat {
  pending_orders: number  // 待支付订单数（status = 0）
  open_tickets: number    // 未关闭工单数（status = 0）
  invitees: number        // 已邀请注册的用户数
}
```

### 2.3 POST `/user/password` 修改密码

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `old_password` | string | 是 | 旧密码 |
| `new_password` | string | 是 | 新密码，至少 8 个字符 |

响应 `data: true`。**成功后该用户全部会话（包括当前）失效，前端应清除 token 并跳转登录。**

错误：`Old password cannot be empty` / `New password cannot be empty` / `Password must be greater than 8 digits`（422）；`The old password is wrong`（400）。

### 2.4 GET `/user/sessions` 活动会话

```ts
interface Session {
  id: string            // 会话 ID（用于删除）
  ip: string            // 登录 IP
  ua: string            // 登录时的 User-Agent
  login_at: UnixSeconds // 登录时间
  current: boolean      // 是否当前请求所用的会话
}
// data: Session[]，按 login_at 倒序
```

### 2.5 DELETE `/user/sessions/:id` 删除会话

路径参数 `id` 为会话 ID。响应 `data: true`（ID 不存在也返回 true）。删除 `current = true` 的会话等于退出登录。

> 原生 API 没有单独的“退出登录”接口，退出可以调用此接口删除当前会话，或仅在前端丢弃 token。

### 2.6 POST `/user/telegram/unbind` 解绑 Telegram

无请求体。响应 `data: true`。失败：`Unbind telegram failed`（400）。

### 2.7 POST `/user/commission/transfer` 佣金划转到余额

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `amount` | number | 是 | 划转金额，**分**，≥ 1 |

### 2.9 订阅（单账号多订阅）

```ts
interface Subscription {
  id: number
  name: string                    // 备注名（用户可改，可能为空串）
  is_primary: boolean             // 是否主订阅（每个用户有且只有一个，列表中排第一）
  plan: { id: number; name: string } | null   // 所属套餐，null 表示没有套餐
  transfer_enable: Bytes          // 总流量（字节）
  u: Bytes                        // 已用上行（字节）
  d: Bytes                        // 已用下行（字节）
  device_limit: number | null     // 设备数限制，null 不限
  speed_limit: number | null      // 限速（Mbps），null 不限
  expired_at: UnixSeconds | null  // 到期时间，null 表示长期有效
  auto_renewal: boolean           // 到期自动续费（用余额）
  remind_expire: boolean          // 到期提醒
  remind_traffic: boolean         // 流量提醒
  banned: boolean                 // 订阅是否被封禁
  reset_day: number | null        // 距下次流量重置的天数；null 表示不重置（一次性套餐、已到期、无套餐、重置方式为“不重置”）
  alive_ip: number                // 当前在线设备数
  subscribe_url: string           // 订阅链接
  allow_new_period: boolean       // 系统是否允许“提前开始新周期”（全局设置，所有订阅相同）
  created_at: UnixSeconds
}
```

- 剩余流量 = `transfer_enable - u - d`。
- 订阅“可用”的判断（与后端一致）：`!banned && transfer_enable !== 0 && (expired_at === null || expired_at > now)`。
- `subscribe_url`：若后台把订阅链接方式设为一次性 / 限时（TOTP），**每次请求返回的链接可能不同**，不要长期缓存。

#### GET `/user/subscriptions`
响应 `data: Subscription[]`，主订阅在前，其余按 ID 升序。

#### GET `/user/subscriptions/:id`
响应 `data: Subscription`。不属于当前用户或不存在：404 JSON `The subscription does not exist`；`id` 非正整数：422。

#### PUT `/user/subscriptions/:id` 修改订阅设置

所有字段可选，**未传的字段不修改**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 备注名，去首尾空格后最长 64 个字符 |
| `auto_renewal` | `0 \| 1` | 自动续费。**注意是整数 0/1，不是 boolean**（传其它值返回 422） |
| `remind_expire` | `0 \| 1` | 到期提醒 |
| `remind_traffic` | `0 \| 1` | 流量提醒 |

响应 `data: true`。错误：422（参数不合法）、404（订阅不存在）、`Save failed`（400）。

#### POST `/user/subscriptions/:id/reset-security` 重置订阅链接

无请求体。重置订阅的 uuid 与 token，**旧订阅链接与客户端节点认证立即失效**。响应 `data: string`（新的订阅链接）。

#### POST `/user/subscriptions/:id/new-period` 提前开始新周期

流量用完后，扣除“距下次重置的天数”换取立即清零流量。无请求体。响应 `data: true`。

规则与错误：
- 系统关闭此功能（`allow_new_period = false`）：`Renewal is not allowed`（403）——前端应根据订阅的 `allow_new_period` 决定是否显示按钮
- 流量未用完：`You have not used up your traffic, you cannot renew your subscription`（400）
- 订阅不重置流量（`reset_day` 为 null）：`You do not allow to renew the subscription`（400）
- 剩余有效期不足一个重置周期 + 1 天：`You do not have enough time to renew your subscription`（400）
- `Invalid reset period`（400）、订阅不存在（404）

成功后：`expired_at` 减去 `reset_day` 天（按月重置的若 `reset_day` 为 0 则减 30 天，按年减 365 天），`u`、`d` 清零。

### 3.1 枚举


### 3.3 GET `/user/orders` 订单列表

Query：`status`（可选，整数，见 `OrderStatus`；非整数返回 422）。不分页，按创建时间倒序。

```ts
interface OrderView {
  trade_no: string                 // 订单号（所有订单接口用它定位）
  plan_id: number                  // 0 表示充值
```

### 3.4 POST `/user/orders` 下单

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `plan_id` | number | 是 | 套餐 ID；**0 表示充值** |
| `period` | Period | 是 | 付款周期；充值时传 `"deposit"` |
| `coupon_code` | string | 否 | 优惠券码（充值不使用） |
| `deposit_amount` | number | 充值时必填 | 充值金额（**分**），> 0 且 < 9999999 |
| `subscription_id` | number | 否 | **0 或不传 = 新开一个订阅**；非 0 = 对该订阅续费 / 升级 / 购买重置包 |
| `immediate` | boolean | 否 | 只对**同套餐续费**的周期订单有效：`false`（默认）= 提前续费，到期时间顺延、已用流量要到重置日才重置；`true` = 立刻生效新套餐，开通时清零已用流量，并从到期时间中扣除本流量周期剩余的时间（本周期结束时间 = 下次流量重置时间与到期时间中较早的一个；套餐不重置流量时为到期时间）。其他订单类型忽略 |

响应 `data: string`（订单号 `trade_no`）。下单后跳转订单详情页，再调用 checkout。

金额计算顺序：套餐价格 → 优惠券 → 会员折扣 → 升级折抵（如适用）→ 插件过滤 → **自动用账户余额抵扣**（余额足够则全额抵扣，`total_amount` 变 0）。插件的调整明细随订单保存，见 3.5 的 `adjustments`。

业务错误：

| 条件 | HTTP | 文案原文 |
|---|---|---|
| period 为空 / 不在枚举内 | 422 | `Plan period cannot be empty` / `Wrong plan period` |
| **已有待支付或开通中的订单（按用户整体判断）** | **409** | `You have an unpaid or pending order, please try again later or cancel it` |
| 充值金额 ≤ 0 / 过大 | 422 | `Failed to create order, deposit amount must be greater than 0` / `Deposit amount too large, please contact the administrator` |
| 套餐不存在 | 400 | `Subscription plan does not exist` |
| 套餐容量已满（新购 / 换套餐时） | 400 | `Current product is sold out` |
| 套餐未提供该周期价格 | 400 | `This payment period cannot be purchased, please choose another period` |
| 重置包：未指定订阅、订阅不可用或不是同一套餐 | 400 | `Subscription has expired or no active subscription, unable to purchase Data Reset Package` |
| 套餐已停售（且不是续费本套餐） | 400 | `This subscription has been sold out, please choose another subscription` |
| 套餐不允许续费 | 400 | `This subscription cannot be renewed, please change to another subscription` |
| 停售可续费套餐但订阅已不可用 | 400 | `This subscription has expired, please change to another subscription` |
| 换套餐功能关闭 | 403 | `Changing the subscription is not allowed at present, please contact customer service or submit a ticket` |
| **新开订阅时订阅数量达到上限** | **403** | `The number of subscriptions has reached the limit` |
| 指定的订阅不存在 | 404 | `The subscription does not exist` |
| 优惠券相关 | 400 | 见 3.9 |

### 3.7 POST `/user/orders/:trade_no/checkout` 结算

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `method` | number | 应付 > 0 时必填 | 支付方式 ID（来自 `GET /user/payment-methods` 的 `id`） |
| `token` | string | StripeCredit 时必填 | Stripe.js 生成的卡片 token |

```ts
interface CheckoutResult {

  data: unknown

```

| type | 含义 | data | 前端处理 |
|---|---|---|---|
| -1 | 应付金额为 0，已直接标记支付并开通 | `true` | 刷新订单状态 |
| 0 | 展示二维码 | string（二维码内容 / URL），个别网关可能为 null 或对象 | 用 data 生成二维码，并轮询 `status` |

| 2 | 已直接扣款（StripeCredit） | `true` | 轮询 `status` |

### 3.9 POST `/user/coupons/check` 校验优惠券

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | string | 是 | 优惠券码 |
| `plan_id` | number | 否 | 传 0 / 不传则不检查套餐限制 |

## 6. 工单与提现（`internal/ticket`）

需要登录。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/user/tickets` | 我的工单 |
| GET | `/user/tickets/:id` | 工单详情（含消息） |
| POST | `/user/tickets` | 新建工单 |
| POST | `/user/tickets/:id/reply` | 回复 |
| POST | `/user/tickets/:id/close` | 关闭 |
| POST | `/user/withdrawals` | 佣金提现申请 |

```ts
enum TicketLevel { Low = 0, Medium = 1, High = 2 }
enum TicketStatus { Open = 0, Closed = 1 }
enum TicketReplyStatus {
  Pending = 0,  // 待回复（最后一条是用户消息）
  Replied = 1,  // 已回复（最后一条是客服消息）
}

interface Ticket {
  id: number
  user_id: number
  subject: string
  level: TicketLevel
  status: TicketStatus
  reply_status: TicketReplyStatus
  subscription_id: number | null   // 关联订阅
  created_at: UnixSeconds
  updated_at: UnixSeconds
}
interface TicketMessage {
  id: number
  user_id: number
  ticket_id: number
  message: string
  created_at: UnixSeconds
  updated_at: UnixSeconds
  is_me: boolean        // 是否当前用户发送（false 为客服）
}
interface TicketDetail extends Ticket {
  messages: TicketMessage[]   // 按时间正序
}
```

### 6.1 GET `/user/tickets`
`data: Ticket[]`，按创建时间倒序，不分页。

### 6.2 GET `/user/tickets/:id`
`data: TicketDetail`。不存在：404 JSON `Ticket does not exist`。

### 6.3 POST `/user/tickets` 新建

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `subject` | string | 是 | 主题，最长 255 个字符 |
| `level` | 0 \| 1 \| 2 | 是 | 优先级：0 低、1 中、2 高 |
| `message` | string | 是 | 内容，最长 10000 个字符 |
| `subscription_id` | number | 否 | 关联订阅（必须属于当前用户） |

响应 `data: Ticket`。

错误：`Ticket subject cannot be empty` / `Ticket subject cannot exceed 255 characters` / `Ticket level cannot be empty` / `Incorrect ticket level format` / `Message cannot be empty` / `Message is too long` / `Invalid parameter`（422）；**`There are other unresolved tickets`（400，同一用户只能有一个未关闭工单）**；`Please purchase a plan before opening a ticket`（400，后台设置仅限付费用户）；`Opening tickets is not allowed at present`（400）；订阅不存在（404）。

### 6.4 POST `/user/tickets/:id/reply`

请求体 `{ "message": string }`（必填，最长 10000）。响应 `data: true`。

错误：`The ticket is closed and cannot be replied`（400）；**`Please wait for the technical enginneer to reply`（400，最后一条消息是自己发的，必须等客服回复后才能再发）**；工单不存在（404）。

> 已回复且 24 小时无新消息的工单会被系统自动关闭。

### 6.5 POST `/user/tickets/:id/close`
无请求体。响应 `data: true`。

### 6.6 POST `/user/withdrawals` 佣金提现申请

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `withdraw_method` | string | 是 | 提现方式，必须是后台设置 `commission_withdraw_method` 中的一项（如 "支付宝"、"USDT"） |
| `withdraw_account` | string | 是 | 提现账号，最长 255 个字符 |

响应 `data: Ticket`（以系统名义创建的高优先级工单，标题与内容按 `Content-Language` 语言写入）。

错误：`The withdrawal method cannot be empty` / `The withdrawal account cannot be empty` / `The withdrawal account is too long`（422）；`Unsupported withdrawal`（400，提现功能关闭）；`Unsupported withdrawal method`（400）；`The current required minimum withdrawal commission is :limit`（400，`limit` 单位为**元**）。

> ⚠️ 原生 API **目前没有接口返回可用的提现方式列表、是否关闭提现、最低提现金额**（这些在 `/api/v1` 兼容层的 `user/comm/config` 里才有），见文末“缺口”。

## 9. 订阅节点与客户端（`internal/subscribe`）

| 方法 | 路径 | 认证 | 说明 |
|---|---|---|---|
| GET | `/user/subscriptions/:id/servers` | 登录（Authorization） | 订阅可用节点列表（ETag） |
| GET | `/client/app/config` | `?token=` 订阅 token | App 内置 Clash 配置（YAML 文本） |
| GET | `/client/app/version` | `?token=` 订阅 token | App 版本信息 |

### 9.1 GET `/user/subscriptions/:id/servers`

```ts
interface ServerView {
  id: number | string
  type: string                    // 协议类型，例如 "vmess"、"vless"、"trojan"、"shadowsocks"、"hysteria"、"tuic"…
  protocol?: unknown              // 部分类型存在
  name: string
  rate: number | string           // 倍率（数据库原值，可能是 "1.00" 这样的字符串，建议 Number() 处理）
  tags: string[] | null
  is_online: 0 | 1                // 5 分钟内有心跳为 1
  last_check_at: UnixSeconds | null
  cache_key: string               // 节点状态指纹
}
// data: ServerView[]
```

- 只返回展示字段，不含地址、端口等连接信息。
- 订阅不可用（封禁 / 到期 / 无流量 / 用户封禁）时返回空数组。
- 订阅不存在：404 JSON `The subscription does not exist`。

**ETag 行为**：
- 响应头 `ETag: "<sha1>"`（基于所有节点 `cache_key` 计算）。
- 请求头 `If-None-Match` 包含当前 ETag 时，返回 **HTTP 304、无响应体**（不是 JSON）。
- 前端注意：
  1. axios 默认把 304 当作错误（`validateStatus` 只接受 2xx），如需手动发 `If-None-Match`，需放宽 `validateStatus` 并沿用本地缓存数据；
  2. **分离部署跨域时**：CORS 预检不允许 `If-None-Match` 请求头、也没有暴露 `ETag` 响应头，手动携带会导致预检失败——跨域场景下**不要手动设置 `If-None-Match`**，交给浏览器 HTTP 缓存自动协商即可；同源（不分离部署）可以手动使用。

### 9.2 GET `/client/app/config`

Query：`token`（订阅 token，即订阅链接中的 token 参数）、`flag`（可选）。返回 Clash YAML 配置文本（非 JSON），供 App 使用；订阅不可用时节点为空。token 缺失 / 无效：统一 404 页面。

### 9.3 GET `/client/app/version`

Query：`token`（必填）。返回标准 JSON 包装：

```ts
// 一般情况
interface AppVersions {
  windows_version: string
  windows_download_url: string
  macos_version: string
  macos_download_url: string
  android_version: string
  android_download_url: string
}
// User-Agent 含 "tidalab/4.0.0" 或 "tunnelab/4.0.0" 时只返回对应平台：
interface PlatformVersion { version: string; download_url: string }
```

token 缺失 / 无效：统一 404 页面。

> 这两个接口面向客户端 App，用户端网页一般不需要调用。

## 11. 插件路由（`internal/plugin`）

| 方法 | 路径 | 说明 |
|---|---|---|
| ANY | `/plugin/{code}/*path` | 插件的访客路由与用户路由 |

（插件管理端路由在 `{api}/{secure_path}/plugin/{code}/*`，不属于本文范围。）

- `{code}` 为插件代码。插件不存在、未启用、没有对应路由时返回**统一 404 页面**。
- 插件在注册时决定每个路由是**访客**（无需登录）还是**用户**（需登录）。用户路由同样通过 `Authorization: Bearer <token>` 认证，失败时返回与核心接口相同的 401 / 403 JSON。
- 响应格式：
  - Go 插件使用 SDK 的 `OK` / `Fail` 时，与核心接口相同的 `{code, msg, data}`；
  - JS 插件路由返回普通值时包装为 `{code: 0, msg: "ok", data: <返回值>}`；返回失败对象时为 `{code: <状态码>, msg}`（HTTP 状态码同 code）；也可以返回原始响应（自定义状态码、Content-Type、内容）；
  - 插件执行异常：500 `{code: 500, msg: "插件执行失败"}`。
- 具体路径与参数由各插件自行定义，管理端插件详情中可看到路由列表（`method`、`path`、`scope`）。

### 11.1 GET `/user/plugin-widgets` 插件卡片（需登录）

查询参数 `slot`：卡片位置，目前只有 `dashboard`（默认），其它值返回 422。返回已启用插件在该位置的卡片，按插件代码与注册顺序排列；没有卡片时为 `[]`。

```ts
interface PluginWidget {
  plugin: string  // 插件代码
  key: string     // 插件内唯一的卡片标识
  slot: string
  title: string
  icon: string    // puzzle / gift / calendar-check / star / trophy / ticket / sparkles / coins / megaphone / ferris-wheel / key / users / book / shield，未知值按 puzzle 显示
  state: string   // 卡片状态路由，如 "/widget"
}
```

前端按以下规则显示：

1. `GET /plugin/{plugin}{state}` 取得卡片状态 `{ hidden?: boolean; text?: string; value?: string; actions?: { label: string; path?: string; link?: string; disabled?: boolean; confirm?: string }[] }`，请求失败或 `hidden` 为 `true` 时不显示该卡片。
2. `text`、`value`、`label` 以**纯文本**显示，不能按 HTML 渲染；分别截断到 200、32、16 个字符，按钮最多 2 个。
3. `state` 与按钮 `path`、`link` 必须匹配 `^/[A-Za-z0-9_/-]{0,127}$`，不匹配的忽略，避免请求到插件前缀之外的接口。
4. 点击按钮：`confirm` 不为空时先确认；按钮有 `link` 时跳转到该用户端页面（如 `/plans`），不发请求；否则以 POST 请求 `/plugin/{plugin}{path}`，成功时显示返回数据中的 `message`（没有时显示通用成功提示），之后重新获取该卡片状态与 `/user/info`；失败时显示错误信息。

### 11.2 GET `/user/plugin-pages` 插件页面（需登录）

返回已启用插件的用户端页面，按插件代码与注册顺序排列；没有页面时为 `[]`。

```ts
interface PluginPage {
  plugin: string                    // 插件代码
  key: string                       // 插件内唯一的页面标识
  title: string                     // 最多 24 个字符
  titles?: Record<string, string>   // 其它语言的标题，如 { "en-US": "Lucky Wheel" }
  icon: string                      // 同 11.1 卡片图标
  group: 'subscribe' | 'finance' | 'more' | 'user'  // 侧边导航分组
  content: string                   // 页面内容路由，如 "/page"
}
```

前端按以下规则显示：

1. 侧边导航按分组追加页面，链接为 `/plugin/{plugin}/{key}`，标题取当前语言的 `titles`，没有时用 `title`（纯文本）；分组顺序建议为：主菜单、订阅、财务、更多、用户。
2. 打开页面时 `GET /plugin/{plugin}{content}` 取得 `{ blocks }`，按区块渲染：`markdown`（不解析 HTML 与图片）、`alert`、`fields`、`table`、`actions`。字段、长度限制与按钮行为见《插件开发说明》第 6 节；所有文字按纯文本显示，`content` 与按钮 `path` / `link` 的规则同 11.1。
3. 页面不在列表中（插件未启用）时提示页面不存在。
4. 主题可以为特定插件页面提供专门界面（默认主题：`lucky_wheel` / `wheel` 显示转盘），此时不请求 `content`。

## 13. 已发现的缺口与注意事项（供前后端讨论）

1. **（已解决：单元 19 新增 `GET /user/config`，见 2.10）缺少“用户端公共配置”接口**：原项目 `user/comm/config` 返回的 `currency`、`currency_symbol`（货币符号）、`withdraw_methods`、`withdraw_close`、`commission_withdraw_limit`、`commission_distribution_*`、`is_telegram`、`stripe_pk` 等，在原生 API 中**没有对应接口**（只在默认关闭的 `/api/v1` 兼容层中存在）。其中 Telegram 相关可用 `GET /user/telegram` 代替、Stripe 公钥可用 `stripe-key` 代替，但**货币符号、提现方式列表、是否关闭提现、最低提现金额**前端目前无法从原生 API 获取，需要后端补充（例如扩展 `GET /site` 或新增 `GET /user/config`）。
2. **分页返回格式不一致**：公告是 `{total, list}`，佣金明细是 `{total, data}`。
3. **布尔字段风格不一致**：`PUT /user/subscriptions/:id` 用 `0/1` 整数；`PUT /user/telegram/prefs` 用 boolean；模型透传字段（`Plan.show`、`Notice.show` 等）是 `0/1`。
4. **404 有两种**：业务不存在是 JSON，路由不存在 / token 无效是 HTML 页面。
5. **退出登录**：没有专用接口，可用 `DELETE /user/sessions/:id` 删除当前会话（从 `GET /user/sessions` 中 `current = true` 的项取 ID）。
